## 0. Коротко

1. **Каркас сильний у головному** — пам'ять лише в репо, гейти з зубами, журнал точності гачків. Таких речей у документації Claude Code нема, це власний здобуток. Слабке місце — не правила, а **доставка**: частина механіки тримається на тому, чого документація не обіцяє, і на тексті там, де вже є рідний механізм.
2. **Три дешеві виправлення з певним ефектом** (кожне — до 15 рядків): друга частина профілю повторюється в контексті після кожної паузи сесії (у цій сесії — 4 зайві копії за 2,5 год); `env_check` у сесії з кількома репо досі запускається руками; гачок пам'яті вгадує рішення за списком слів (точність 36 %) — замість цього можна перевіряти рядок «пам'ять: …», який профіль уже вимагає.
3. **Один ризик, який варто перевірити першим:** setup script у нових сесіях не виконується — береться знімок диска (кеш середовища). Чи є ядро в сесії **лише з продуктом**, залежить від того, яка сесія зробила знімок. Якщо нема — гачки й профіль там мовчать без жодного попередження. Перевірка — одна хвилина (§6, П1).
4. **Каркас не користується трьома рідними механізмами Claude Code:** skills (процедури на виклик), правила з `paths:` на рівні користувача (підказка приходить у мить, коли агент торкається файла), подія `PreCompact` (інструкції для стиснення — закриває `CTX-1`, що висить 33 дні).
5. **Нове репо «за один хід» сьогодні — це 10 файлів руками.** Чернетка скрипта-закладача готова й перевірена: `frame_check` після нього дає ✓ (§4, Ч6). Заодно знайдено: `frame_check` дає ✓ і на шаблонах, у яких нічого не заповнено.
6. **Дублі:** правило аудиту переказано в шести місцях, «інша модель — наперед» — у п'яти; шаблон `CLAUDE.md` велить кожному репо повторювати профіль, хоча його ж розділ каже «лише відмінності».
7. **Не беремо** (з джерелом, щоб не розвідувати вдруге): плагіни — у хмарній сесії не вантажаться; автопам'ять — живе на машині; гачки-судді на моделі — для наших задач не бачать потрібного тексту.

### Ч4. Гачок пам'яті за заявленим рядком [перевірено: 7 випадків з 7]

Заміна функції `verdict` у `memory-guard.sh`. Частина про примірку лишається як є.

```python
LINE = re.compile(r"(?mi)^[\s>*_`-]*пам['’ʼ]ять\s*[:—-]\s*(.+)$")
NONE = re.compile(r"(?i)нового\s+нема")
SHA  = re.compile(r"\b[0-9a-f]{7,40}\b")
def git(repo, *a):
    return subprocess.run(['git', '-C', repo, *a], capture_output=True, text=True).stdout.strip()
def repos(root):   # репо сесії; клон «лише для читання» (.git/lens-readonly) не судимо — як handoff-remind
    return [os.path.join(root, d) for d in sorted(os.listdir(root))
            if os.path.isdir(os.path.join(root, d, '.git')) and not os.path.exists(os.path.join(root, d, '.git', 'lens-readonly'))]
def verdict(d, root='/home/user'):
    if d.get('stop_hook_active'): return None
    m = LINE.findall(d.get('last_assistant_message') or '')
    if not m:
        return "Гачок пам'яті: у відповіді нема рядка «пам'ять: <коміт> (доми)» або «пам'ять: нового нема» (профіль, ЗВІТ). Допиши його — або запиши зміст ходу в репо й назви коміт."
    claim = m[-1]
    dirty = [os.path.basename(r) for r in repos(root) if git(r, 'status', '--porcelain', '--untracked-files=no')]
    ahead = [os.path.basename(r) for r in repos(root)
             if git(r, 'rev-parse', '--abbrev-ref', '@{u}') and git(r, 'rev-list', '--count', '@{u}..HEAD') not in ('', '0')]
    if NONE.search(claim):
        if dirty or ahead:
            return ("Гачок пам'яті: рядок каже «нового нема», а в репо є незбережене — незакомічене: " + (', '.join(dirty) or '—') +
                    "; не на GitHub: " + (', '.join(ahead) or '—') + ". Закоміть і запуш, або одним рядком поясни, чому це лишається.")
        return None
    shas = SHA.findall(claim)
    if not shas:
        return "Гачок пам'яті: у рядку «пам'ять: …» нема ні хеша коміту, ні «нового нема»."
    for s in shas:
        if not any(subprocess.run(['git', '-C', r, 'cat-file', '-e', s + '^{commit}'], capture_output=True).returncode == 0 for r in repos(root)):
            return f"Гачок пам'яті: коміту {s} з рядка «пам'ять: …» нема в жодному репо сесії — хеш з голови?"
    if ahead:
        return "Гачок пам'яті: коміт названо, але HEAD ще не на GitHub у: " + ', '.join(ahead) + " — push і read-back."
    return None
```

Перевірені випадки: рядка нема → блок · «нового нема», дерево чисте → тиша · коміт названо, він є і на GitHub → тиша · хеш з голови → блок · «нового нема» при незакоміченому → блок · коміт є, але не запушено → блок · повтор через гачок → тиша.

Чого не перевірено: поведінку на відповіді-питанні без жодної роботи (профіль вимагає рядок і там, тож блок формально слушний); репо без віддаленої гілки — такі не судяться.

Чому це краще за гачок-суддю на моделі: `type: "prompt"` на події `Stop` бачить лише вхід гачка — останню відповідь агента, а не слова Konst; на `UserPromptSubmit` бачить слова Konst, але вміє тільки зупинити хід (hooks «Response schema»). Для «чи вирішив щось Konst» жоден варіант не годиться.
