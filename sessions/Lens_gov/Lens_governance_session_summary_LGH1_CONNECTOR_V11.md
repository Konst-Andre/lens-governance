## Правила, що народились у сесії (14.29, повним текстом)

- **П-LGH1** (з LGH-0) · Секрети — руками власника. Токени й ключі в секрети інфраструктури вносить Konst сам у дашборді; агент дає інструкцію й назви, але не переносить токен у сервіс. Деплой коду з `keep_bindings` — дозволено: секретів не торкається.
- **П-LGH2** (з LGH-0, уточнено) · Запис у GitHub — лише через конектор: dry_run → мікроскоп → «так» Konst → `gh_commit` з `expected_head` (тепер обовʼязковий у коді). Один хід = один `gh_commit`.
- **П-LGH3** (з LGH-0) · Засвічений у чаті секрет = секрет під ротацію.
- **П-LGH4** · Видалення гілки — лише на пряме слово Konst і після звірки, що унікального вмісту нема (порівняти з `main`). Класифікатор середовища блокує видалення без такого слова — не обходити.
- **П-LGH5** · Project — робочий простір агента: агент сам створює й видаляє доки Project без нагадування Konst. Project = незмінне + транспорт. Видалення з Project — лише коли файл має дім (репо) і read-back ≡, або коли файл сам каже «живе доки», і умова виконана.
- **П-LGH6** · Канон Lens ≠ проєкти для інших людей. Інфраструктура чужого проєкту (ae-edit, ae-proxy) живе у своєму репо, не в `lens-governance`.
- **П-LGH7** · Естафета самері (слово Konst 26.09: «добра структура, такої в мене нема»). На закритті сесії: (1) самері → **репо** (дім, канон); (2) та сама копія → **Project** (транспорт: наступний чат бачить її одразу в контексті, без пошуку в репо); (3) стартове повідомлення §6 називає обидва місця. На старті наступного чату: (4) прочитати копію з Project; (5) звірити з репо (md5 або `gh_read`) — розбіжність = розібратись до роботи, канон — репо; (6) видалити копію з Project (П-LGH5). У Project одночасно живе лише самері останньої сесії.
