# Версія застосунку — B · rev: коли піднімати і як машина стежить

> живе доки: продукти Lens мають застосунок із версією (QR Lens, далі — кожен новий з інтерфейсом). Правило — Konst 18.10.2026 (QR CC-17: «головне, щоб хтось це контролював… і наступні агенти теж»); зміна правила — тут, тим самим комітом (аудит — клас 1).

## 1. Два рівні — як у Apple, наші назви

Світ (18.10.2026): Apple — три числа «велика зміна · менш помітна функція · обслуговування» + окремий номер збірки (macpaw.tech/engineering/versioning-for-ios-and-macos); SemVer — для бібліотек, де важлива сумісність, CalVer (рік.місяць) — для релізів за розкладом (workos.com/blog/software-versioning-guide). У нас застосунок для людей, не бібліотека, і релізи не за розкладом → **два рівні**:

| підняти | коли | приклад (QR) |
|---|---|---|
| **B** (батч) +1, **rev → 0** | команда помітить нове: новий блок чи екран, нова поведінка, нова мова руху чи матеріалу на кількох екранах | свіжість даних у героблоці + шкала (мав бути B65) |
| **rev** +1 | виправлення, поліш, контраст, текст, дрібний рух — у межах уже знайомого | легенда 4,07 → 4,5 · коментар у коді |
| — (без зміни) | документи, тести, примірки, **дані** (у даних своя «версія» — дата звіту в застосунку) | новий KPI, самері |

Видно людям — у застосунку (QR: шіт «Про застосунок», `APP_BUILD`). Новий B — **новий файл білда** з номером у назві, старий → `archive/builds/`.

## 2. Хто вирішує

Агент — рядком у плані кроку: **«версія: B65.0 — чому»** (або «rev 22 — чому»); Konst підтверджує тим самим «так». Сумнів між B і rev — питання Konst («команда це помітить?»).

## 3. Машина — `tools/claude-code/version_check.py` (selftest 6/6)

Рядок `env_check` продукту порівнює код застосунку з `origin/main`: код змінився, а версія ні → **✗** («забув»); новий B, а rev не 0 → ✗; версія впала → ✗; номер у назві файлу білда ≠ B → ✗; rev стрибнув більше ніж на 1 → ⚠. Що саме підняти — не міряє (це суть зміни), лише що підняв і що чисто. Зміна лише коментаря теж вимагає rev +1 — свідомо: дешево, а машина коментар від коду не відрізнить.

Підхід — «Version Forget-Me-Not» (Simply Business, 2020: diff коду проти бази ⟂ мітка версії), але в `env_check`, а не в CI.

**Як доходить до кожного продукту:** `tools/claude-code/frame_check.sh` (`VER-1`) — репо з інтерфейсом, чий `tools/env_check.sh` не кличе `version_check.py`, на старті сесії бачить ⚠ «не адаптоване»; рядок виклику — `templates/env_check_template.sh` (параметри свого продукту: файл коду, регулярка мітки, назва файлу білда).
