# Примірка — знімки UI-рішень наперед (тека `shots/` продукту)

> живе доки: рішення про вигляд ухвалюють раніше, ніж пишуть код. Дім — `tools/claude-code/` (каркас усіх продуктів).
> Ідея Konst («стенд без стенду», QR-Lens CC-8, 11.10.2026); метод — QR CC-9, 11.10.2026. Пара — `kernel/wsd/Lens_verdict_protocol.md` §2.4 (прев'ю-вибір): §2.4 каже, **як показати** варіанти; цей файл — **як рішення доживе до коду**.
> Ядро публічне: тут лише метод. Знімки з реальними даними живуть у **приватному** репо продукту; у ядро і в публічний `sandbox` — ніколи.

## 1. Що це і навіщо

**Примірка** — як у кравця: варіанти міряють на справжньому тілі (живий білд, справжні дані, кадр телефона), Konst обирає, обране чекає на шиття (код). Тека `shots/` тримає знімки, код накладки й рядок «що обрано і чому», доки рішення не в проді.

Без неї рішення гине так:
1. **Картинки чату зникають з сесією** — наступний агент читає «обрано В» і не знає, як виглядає В. Знімок у репо він відкриває (`Read`) і бачить сам.
2. **Рішення й код розходяться в часі** (вибір у CC-8, код у CC-9+): тека тримає рішення, доки до нього дійде черга.
3. **Дешевше за стенд** — нового інструмента нема, накладка на справжній білд дає чесні заміри (QR: шіт 404 → 420 px).
4. **Приймання**: після коду — знімок «після» тим самим кадром поруч з обраним (машиною — `tools/claude-code/shots_same.py`: кроп того самого стану з примірки ⟂ з коду, обидві теми; QR CC-16: клас значка в коді зайнятий іншим елементом → сірі плитки, очі не побачили, порівняння — так); видно, чи зробили обране, а не схоже.
5. **Банк смаку**: відкинуте з причиною — смак Konst словами; вибір, що повторився, стає рецептом кукбука.

## 2. Коли

**Тригер** — як у §2.4: ≥2 життєздатні варіанти **вигляду**, і вирішити має око Konst, а код буде не в цьому ж ході.
**Не примірка:** вибір логічний (аргумент, не картинка) · різниця видна лише в піксель-зумі · один варіант очевидно правильний · рішення і код в одному ході (тоді досить §2.4 у чаті).

## 3. Як знімати

- **Справжній білд + накладка** (CSS/JS поверх, а не окремий стенд); кожен варіант — свій файл накладки. Кадр — пристрій продукту з `CLAUDE.md` (QR: 375×634, телефон), **обидві теми**, «зараз» першим.
- **До 5 варіантів** (§2.4: >5 — ✗) і **ставка агента з причиною** в тому ж ході.
- **Смуга** «зараз · А · Б · …» з підписами, одна на тему → **WebP q≈80** (замір 11.10.2026: 3060×1060 PNG 384 КБ → WebP 92 КБ, текст читається через `Read`). Видалений файл лишається в історії git назавжди — вага важить **при народженні**, не при видаленні.
- **Огляд очима перед показом — чек-лист** (те, чого машина не міряє; кожен пункт — пропуск Konst): межі сусідів, а не лише «чи з'явилось» (AE S97) · **що правиться — видно в спокої**, не лише при наведенні (AE S99) · **спільний елемент екранів** (шапка, панель) — та сама будова, не схожий вигляд (AE S99) · пояснення — у «i», не абзацом (машиною — `ui_lint` №38) · **вибір зі списку ≠ поле вводу**: випадайка — біла кнопка з ▾, лунка — лише там, де пишуть (AE S99) · **підкладка розділювача чи заголовка групи ≠ тон лунки поля** — інакше зливаються в одну сіру масу (AE S99) · текст для людини — без кодів, номерів і «→» замість слів (AE S99) · **один вигляд — один сенс** (риска «вибрано» ≠ риска «змінено», AE S99) · **повідомлення в рядку — коротко**, подробиці — у панелі (AE S99) · **край картки видно** на тлі (рамка або тінь; тіло таблиці — теж картка, AE S99) · **ПК, не мобайл:** робоча поверхня тягнеться до низу екрана — без «дірки» під короткою таблицею (AE S99).
- **Примірка з поведінкою (клік, перемикач, вікно) — знімальник сам клацає й звіряє наслідок**, а не лише знімає кадри: помилок сторінки 0 (`pageerror`), після дії змінився стан (вибір, вигляд, вікно); `--inject` повертає відому ваду → ✗. Статичний кадр не бачить мертвого кліку (AE S106: накладка затулила `CSS.escape` — плитки не перемикались у двох версіях, знайшов Konst; зразок — `AE-Simulator:docs/shots/AE-ANC_photo/fit_photo_v4_shots.py`). Ім'я змінної накладки — не ім'я вбудованого API (`CSS`, `Image`, `Event`…).
- **Машина на примірці — та сама, що на коді** (пропуск Konst, AE S107, 26.10.2026: 17 вад v4, які знімальник з 7 пунктами не бачив, а `ui_lint` бачив би 3): знімальник примірки (1) віддає сторінку з **CSP проду** (заголовок із `_headers` продукту — без нього «працює» те, що в проді порожнє: фото через `blob:`), чекає опитуванням (`evaluate`, бо CSP не пускає `eval` — `wait_for_function` падає); (2) ганяє **`ui_lint` у станах примірки проти бази попередньої версії** (лише нові ✗); (3) має пункт на кожну ваду, яку назвав Konst, з `--inject`, що повертає саму ваду. Кнопки «що роблять» — у примірці або оживають локально з написом «примірка: не зберігається», або кажуть, що вони макет; мовчазна кнопка — вада подачі.
- **Рецепт, не лише пікселі:** накладки й команда знімання лежать поруч зі знімками. Без них знімок не перезняти, і код не почати з обраного (втрата CC-8: генератор жив у скретчпаді).

## 5. Життєвий цикл

| стан | коли | що в теці | хто переводить |
|---|---|---|---|
| **примірка** | знято ≥2 варіанти, показано Konst | смуги обох тем + накладки + рядок зі ставкою | агент → Konst |
| **обрано** | слово Konst | + вибір і **чому словами Konst**, id черги, куди піде — **у тому ж ході** | Konst; гачок пам'яті стежить |
| **у роботі** | почався код пункту | без змін; перед UI-кодом агент дивиться обране | агент |
| **прийнято** | код у проді **і вирок Konst на пристрої** ✅, знімок «після» поруч з обраним | файли **видалити**; рядок → `DECISIONS.md` репо (нема — бриф пункту черги): «прийнято · коміт · дата», «чому» — назавжди; з README — геть | Konst → агент |
| **відкинуто** | Konst передумав або пункт скасовано | файли видалити; одне речення «чому» — туди ж | Konst |
| **застаріло** | > 14 днів без коду або екран під примірку змінився | ⚠ → перезняти (накладки поруч — дешево) або Konst підтверджує | агент |

**Жива примірка — адресою, не файлом** (Konst 14.10.2026, QR CC-12: «круто, що можна понатискати — але з телефона файл не відкривається»). Файл `.html`, надісланий у чат Claude, на iPhone показується без JS — порожній застосунок. Тому: знімки `.webp` — як завжди, **плюс** жива сторінка (справжній білд + накладка примірки + поля, де Konst сам друкує текст) — **адресою**. Канал залежить від того, що є в продукту (перевірка — `curl -so /dev/null -w '%{http_code}' https://zz123-<воркер>.<субдомен>.workers.dev/`: 302 на вхід = Access є; 404 = прев'ю-адрес нема):

| що є в продукту | канал живої примірки | реальні дані | разово від Konst |
|---|---|---|---|
| воркер + Workers Builds + прев'ю-тригер + Access на `*-<воркер>` (QR, 14.10) | службова гілка `fit` → прев'ю-аліас `fit-<воркер>` (зразок `QR-Lens:tools/qr_fit.sh`, `tools/qr_preview.sh`) | так | нічого |
| воркер без прев'ю-адрес або без Access (AirLens: 404, 14.10) | (а) дані не чутливі — увімкнути прев'ю-адреси, далі як вище, але публічно; (б) чутливі — ще й застосунок Access на `*-<воркер>` | (а) ні · (б) так | (а) «так» на `preview_urls = true` у `wrangler.toml` (це деплой); (б) ще один клік: воркер → Settings → Domains & Routes → Preview URLs → **Enable Cloudflare Access** — політика «Cloudflare Workers Preview URLs» **одна на весь акаунт** і вже є з QR (developers.cloudflare.com changelog «Access for Workers» і workers/previews/custom-domains, 24.09.2026) |
| немає воркера (Pages, GitHub Pages; AE-Simulator — до переїзду на воркер, `tools/cloudflare/CLOUDFLARE.md` §2 п.9: Київстар блокує `*.pages.dev`) | `Konst-Andre/sandbox` → `<репо>/<файл>_vN.html` (`tools/PREVIEW.md`): кожна версія — нова адреса, тож кеш Pages (600 с) не заважає — він тримає лише ту саму адресу | ні — лише синтетичні тієї ж довжини | нічого |

У звіті — посилання, а не файл. Новий продукт — спершу рядок перевірки вище, потім канал з таблиці; рядок таблиці міняється, коли міняється інфраструктура продукту.

**Переїзди.** Між сесіями — самері тримає лише `id` рядка, не копію. **У ядро** — коли вибір повторився у ≥2 продуктах або Konst сказав «так завжди»: рецепт кукбука **текстом** (без знімків з реальними даними), у README продукту — вказівник. **В архів — ніколи** (git пам'ятає: `git show <коміт>:<шлях>`). **У `sandbox`** — лише перезняте на синтетичних даних (`tools/PREVIEW.md` §3 п.8).

## 6. Межі

До 5 варіантів · обидві теми · кадр пристрою · WebP · живих примірок ≤ 5 · тека ≤ 3 МБ · вік ≤ 14 днів. Пороги — рішення агента 11.10.2026 (не замір); зміна — тут.

## 7. Машина (QR CC-9: перевірка й гачки ✅, знімальник — перед першим кодом за приміркою)

- **Перевірка теки** ✅ (`tools/claude-code/shots_check.py`, рядок `env_check` продукту; selftest 11/11): ✗ знімок без рядка · рядок живої примірки без файлів · файли після «прийнято / відкинуто»; ⚠ вік > 14 дн. · тека > 3 МБ · > 5 живих · тека `shots/` у публічному репо. Зуби — `--inject`.
- **Гачки — розширення наявних** ✅ (`tools/claude-code/hooks/`): `memory-guard` (9/9) — Konst назвав варіант, а рядок досі «примірка» → хід не закінчиться; `ui-guard` (15/15) — UI-код при живій «обрано / у роботі», а README в сесії не відкривали → стоп; `ui-review-gate` — пункт ① чек-листа «знімок після поруч з обраним».
- **Знімальник** `shots.mjs` (Playwright; ще нема): білд + накладки → смуга обох тем у WebP; той самий кадр — для «після». Робиться перед першим кодом за приміркою (QR — шапки В).

**Як метод доходить до кожного продукту** (Konst 11.10.2026: «інструмент, про який продукт не знає, не працює»): `shots_check.py` — у `SHARED_TOOLS` `tools/claude-code/frame_check.sh` → репо, чий `env_check` його не кличе, на старті сесії бачить ⚠ «не адаптоване … не кличе shots_check.py»; рядок виклику — `templates/env_check_template.sh` (свіжий з ядра, не копія); тека й README — `ADOPT.md` етап 4-а для продуктів з інтерфейсом. Гачки й так діють у всіх сесіях (setup script v3), але без теки мовчать.

Доки знімальника нема — знімає агент руками (Playwright у контейнері); стан — QR самері CC-9 §0.

## 8. Практика ззовні

- Стани рішення й позначка «витіснено» — ADR (gds-way.digital.cabinet-office.gov.uk/standards/architecture-decision-records, переглянуто 05.03.2026). Беремо стани й «чому» назавжди; **не** беремо «старе не редагувати» — живий README лише для відкритих, закрите — у DECISIONS.
- Знімки варіантів поруч із плюсами й мінусами — шаблон design decision Atlassian (11.10.2026). Беремо: варіанти + ставка + вибір.
- Повторюваний вибір → правило (decision trees Lyft · Doctolib, smart-interface-design-patterns.com/articles/decision-trees, 11.10.2026) → у нас: переїзд у кукбук.
- Бінарні файли в git: видалення не зменшує історію; «зберігай рецепт, не пікселі» (gitprotect.io hidden cost of git repository bloat; joshka.net keep binaries out of source control, 11.10.2026). Беремо: WebP + накладки; **не** беремо LFS — обсяг малий (≤ 3 МБ живих), зайва залежність.
