# Claude Code — що має бути в репо (зразок для всіх проєктів Konst)

> живе доки: Konst працює з Claude Code. Змінилась практика — правиться ЦЕЙ файл; репо підтягують зміни при наступному тригері аудиту.
> дім: `lens-governance:tools/claude-code/` · народилось: AE-Simulator S88 (02.10.2026), репо `AE-Simulator` (приватне — інші сесії його не бачать, тому зразок тут)

**Навіщо.** Профіль Konst приходить у кожну сесію, але файли — ні. Практика, народжена в одному репо, інші репо не знає.
Цей файл — єдиний дім зразка: агент будь-якого репо бере звідси те, чого в репо бракує.

## Чекліст репо (що є — пропустити; чого нема — сказати Konst, запропонувати окремим ходом і створити після «так»)

| файл у репо | що | зразок |
|---|---|---|
| `CLAUDE.md` (корінь) | правила роботи агента в цьому репо: мова, гілка, старт сесії, гейти, секрети, деплой, самері; «тут інакше» відносно профілю. До ~200 рядків, подробиці — посиланнями | приклади: `AirLens:CLAUDE.md` · `AE-Simulator:CLAUDE.md` |
| `docs/AUDIT.md` | журнал аудиту інструкцій: тригери · як · журнал | `AUDIT_template.md` (ця тека) |
| `tools/audit_prompts.sh` | подвійний `/doctor prompt-audit` двома моделями | `audit_prompts.sh` (ця тека) — копіювати як є |
| `tools/env_check.sh` | старт сесії одним прогоном: база · мережа · змінні так/ні · гейти · чи прод ≡ репо; нагадує про аудит старше 30 днів | приклади: `AirLens:tools/env_check.sh` · `AE-Simulator:tools/env_check.sh`; рядок нагадування — нижче |
| `.claude/hooks/session-start.sh` + `.claude/settings.json` | інструменти гейтів ставляться самі на старті хмарної сесії | skill `session-start-hook` у Claude Code |
| `docs/summary/<Продукт>_SUMMARY_<дата>[_sN].md` | самері: §0 «ВІДКРИТЕ» зверху, стартове повідомлення в кінці | — |

Рядок нагадування для `tools/env_check.sh` (bash):
```bash
last=$(grep -m1 -oE "^\| 20[0-9]{2}-[0-9]{2}-[0-9]{2}" docs/AUDIT.md 2>/dev/null | tr -d '| ')
if [ -n "$last" ]; then days=$(( ( $(date +%s) - $(date -d "$last" +%s) ) / 86400 )); [ "$days" -gt 30 ] && echo "аудит правил: $days дн. — ПОРА" || echo "аудит правил: $days дн. тому"; else echo "аудит правил: журналу нема"; fi
```

## Практики (повний текст — у профілі Konst; тут — що вони вимагають від репо)

- **Модель і контекст — заміряні.** У хмарній сесії `get_session` (сервер `claude-code-remote`, без `session_id`): `session_context.model` · `effort_level` · `external_metadata.context_usage`. Маркер навантаження — звідти; без інструмента — «≈».
- **Інша модель — лише названа наперед.** `claude -p` чи субагент — рядок у чаті до запуску: модель · effort · навіщо; `--model` завжди явно (CLI в контейнері за замовчуванням — Sonnet, 02.10.2026).
- **Effort.** medium за замовчуванням; «раджу high — чому» в мікроскопі лише на справжній вилці чи незворотному / прод-кроці; перемикає Konst (`/effort`), модель сама не може; на Opus 5.5 / Sonnet 5.5 / Fable 5.1 з підпискою кеш не скидається (code.claude.com/docs/en/prompt-caching, 02.10.2026).
- **Аудит правил.** Змінив файл інструкцій — перед комітом `bash tools/audit_prompts.sh <файл>`; нова модель Claude — усі інструкції; раз на 30 днів. Знайшли обидві моделі — висока впевненість; одна — звірити; застосовується лише підтверджене, після «так». Правки за аудитом повторно не аудитуються.
