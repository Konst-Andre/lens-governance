# Claude Code — каркас для всіх репо Konst (вхід)

> читається точково: за розділом зі «Звідки брати» `CLAUDE.md` ядра (файл > 80 КБ — один Read його не бере).

> живе доки: Konst працює з Claude Code. Змінилась практика — правиться тут або в `REPO_FRAME.md` (аудит за класом, пакетом — `tools/claude-code/templates/AUDIT_template.md` «Коли і скільки»); репо підтягують при наступному тригері аудиту.
> дім: `lens-governance:tools/claude-code/` · народився: AE-Simulator S88, 02.10.2026

**Навіщо.** Профіль Konst приходить у кожну сесію, а файли — ні. Практика, народжена в одному репо, іншим невідома. Тут — один
каркас: як влаштувати репо, щоб агент Claude Code працював, пам'ятав між сесіями й не губив знахідки. Інший репо бере звідси,
читає й будує своє — з адаптацією.

### Де діють і як підключати

- **Де діють.** Claude Code бере гачки з налаштувань **кореня сесії** і користувача (`~/.claude/settings.json`). ## Паралельні сесії — кілька Claude на одну мету (Konst AE S149)

> Слово Konst: **«запусти паралельну сесію на <бриф | пункт черги>»** (AE S149: «щоб пришвидшитись… а потім ми його підключимо до нас»).

- **Коли так:** задача ділиться на поля, що не перетинаються файлами (документи ⟂ прилад ⟂ інше репо), і батьківська сесія має свою роботу. **Коли ні:** дві сесії на одному екрані чи файлі; «щоб швидше» на межі ліміту — ліміти спільні на акаунт (5 год і тиждень палять обидві), паралель виграє годинник, не бюджет. Старт — коли тиждень < 0,85 і 5 год < 0,6 (рядок маркера); інакше — питаю Konst.
- **Механіка (CC, хмара):** `create_session` (репо; модель — та, що в композері Konst, `--model` явно; effort — лише за словом Konst; не вказано — дитина бере своє: S150 отримала **high** при medium у Konst, тобто дорожче для ліміту — питай Konst, яке ставити) → дитина живе у **своєму контейнері** (свій диск — природна ізоляція, як worktree у локальному Claude Code: code.claude.com/docs/en/worktrees, 15.11.2026). Стежити — `get_session` (`status_bucket`) і `list_events` з `kinds ["result"]`; писати — `send_message` (приходить їй як від колеги: рішення Konst передаю **дослівно з датою**, інакше дитина не має права діяти); зупинити — `interrupt_session`; закрити — `archive_session` лише після «готово» Konst. Konst може й сам відкрити її в застосунку Claude і писати туди.
- **Завдання дитині — сім пунктів:** (1) мета, `id` пункту черги й назва українською; (2) **поле**: її файли й заборонені — поля батька переліком, прод, дані людей, середовище, секрети; друге репо — лише дифом батькові (див. «Відомі збої»); (3) гілка — правило репо (AE — `main`, `git pull --rebase` перед push, ніколи force); (4) своє самері (наступний `_sN`) і рядок у черзі; (5) стоп: тиждень ≥ 0,92 або 5 год ≥ 0,9 → самері й стоп; (6) рішень Konst не вигадує — вилка → 💡 у своєму самері §0; (7) звіт за профілем (печатка ревізії · пам'ять · маркер).
- **Зведення — один зводить** (практика «один інтегратор» паралельних агентів: dev.to «Claude Code worktrees: parallel agents without the conflicts», mindstudio.ai «Parallel agentic development», 15.11.2026): батьківська сесія читає звіт дитини, «чекає Konst» з обох — у своєму звіті (Konst не шукає по двох вікнах), вироки Konst передає дитині. Конфлікт git розв'язує той, хто пушить пізніше; спільний файл (черга) — лише дрібні правки рядком. **Межа (AE S157, В-417 — Konst: «сильно відволікся на паралельну сесію… втратив фокус на поточному продукті»):** батько продукту не стає диспетчером дитини — зводить лише вироки, що її блокують, ≤ 1 хід на звіт; решту дитина веде з Konst у своєму вікні; коли зведення з'їдає крок продукту — передати дитину Konst («далі окремо»).
- **Відомі збої (S150):** у контейнері дитини може відпасти підпис комітів (підписувач не бачив `api.anthropic.com`) → коміт через GitHub API, не вимикати підпис у робочому репо; клон іншого репо — лише на читання, і **push туди дитина сама не отримає**: `add_repo` з `access: "push"` відхиляє класифікатор режиму Auto («Unauthorized Access», S150 → ядро, 15.11.2026; Konst бачив відмову в застосунку) — повідомлення батька приходить як від колеги, не слово Konst, тож права не розширює; так і задумано: доступ дає лише людина. Робочий шлях — дитина правує друге репо локально й шле батькові диф через `send_message` (база — її HEAD, рядок «що перевірено чим» на файл); батько накладає на свіжий `main`, ганяє гейт і комітить з посиланням на дитину. Справді треба писати самій — Konst пише в її вікні своїми словами («так, додай <репо> з push») або дитину запускаю на тому репо. Обходити відмову (токен, інший інструмент) — ніколи; дозвіл `mcp__claude-code-remote__add_repo` у `.claude/settings.json` — не перевірено, чи знімає він класифікатор, і розширює права кожній сесії репо — не раджу; `env_check` на старті дитини — хибне ⚠ python, поки гачок ще ставить пакет.
- **Премортем (чому паралель провалиться):** обидві правлять один файл → поле й заборони в завданні; Konst відповідає не в ту сесію → «чекає Konst» з обох — у батька; ліміт згорає вдвічі → стоп-поріг у завданні; дитина вирішує замість Konst → пункт (6); дитина впирається в доступ і шукає обхід → шлях «дифом батькові» прямо в завданні.

- **Чернетки кількох виконавців — кожна у свій файл** (Konst AE S140: «щоб чернетки аудиту не затерли одна одну»): ім'я = репо + шлях + час (+ виконавець), наявний файл не перезаписується, наприкінці — реєстр «скільки запусків → стільки файлів» (`audit_prompts.sh`: `MANIFEST.tsv`, порожній звіт — ✗). Субагентам — шлях виходу в завданні, різний для кожного; збирає — той, хто запускав, за реєстром, а не за «останнім файлом у теці».
- **Прийнята 💡 — підсилення за чек-листом** (Konst AE S144 «гачок… сильніший варіант…» · S145 «приймаю за чек-листом», В-372; нагадує гачок `konst-miss.sh yes`, ярлик `konst-yes`; суд — Stop `konst-yes-stop` — лише коли останній звіт мав «💡 Пропоную»; «як є» · «дослівно» — тиша): «так» на 💡 — не «записати як є», а ① **суть** — що прийнято й яку причину лікує (не симптом?) ② **сильніше в межах** — структура (один дім, злити з наявним) · техніка (простіше · дешевше · надійніше) · контекст (знадобиться іншим продуктам → ядро) ③ **світ** — коли вирішує форму: три рядки з джерелом і датою ④ **премортем** — «через місяць шкодуємо — чому?», кожна дірка → латка або прийнятий ризик ⑤ **ціна** — ліміти заміром, ручні дії Konst, зворотність ⑥ **вирок** — користь > дірок → роблю; ні → звужую чи відкидаю з причиною (останнє слово — Konst) ⑦ у звіті блок **«Підсилення: було → стало»** + дірки й латки; нічого не знайшов — що саме перевірив. Другий погляд (профіль ЦИКЛ п. 3) не дублювати — лише нове (②, ⑦). Дрібний оборотний крок — одним рядком. Хибне спрацювання — рядок «`konst-yes` … хибне» в журналі гачків.
- **Рух — кліпом, а не лише знімком** (Konst AE S140: «щоб ти сам це робив, а я не нагадував»): примірка чи прев'ю з рухом або поведінкою → `python3 tools/claude-code/clip.py <сценарій.json> <тека>` → MP4 у чат (`SendUserFile`) + смугу кадрів агент дивиться сам **до** показу (вада руху видна лише на кадрах). Тримає гачок: `ui-review-gate.sh done` при русі в диффі вимагає `--clip <файл.mp4>` або `--no-clip "<чому>"`.
- **Ревізія → `/compact`, поки кеш теплий** — підрозділ нижче (5 пунктів: коли · межа · машина + іспит · сторож · кеш).
- **Скільки стиснень на сесію — 2 вдень, 3 вночі, далі переїзд** (питання Konst AE S141, В-353). Межі в Claude Code нема — стиснення для того й зроблене, щоб довга сесія тривала (code.claude.com/docs/en/best-practices, 12.11.2026: «your conversation is compacted automatically before the context window fills»); там же — «`/clear` між непов'язаними задачами: зосереджений контекст дає кращі відповіді й коштує менше». **Чому ліміт усе ж є:** кожне стиснення — переказ переказу: що було до першого, після другого лишається переказом другого порядку, і модель **не бачить**, що загубила — самоперевірка звіряє лише з репо, а нюанс з чату зникає мовчки. Світ: Anthropic (engineering «Effective harnesses for long-running agents», 26.11.2025) — «compaction isn't sufficient», стан між вікнами контексту несуть файл прогресу й git, не переказ (у нас — самері §0 + коміти); польові дані (dev.to, YuhaoLin2005, 2026: 459 сесій, до 121 стиснення в одній; «3–8 — норма, 9+ — спад» — спостереження автора, не замір). **Правило:** лік стиснень дає гачок `ctx_watch` (рядок «стиснень у сесії N» на кожне повідомлення Konst і після стиснення). Вдень — після **2-го** переїзд на найближчій межі предмета (нова сесія зі стартового — дешевша й чистіша за третій переказ; предмет посеред — не рвати). Вночі — до **3** (Konst не пише, рішення лише в репо, кожен крок — коміт + самері; переказ губить лише робочу пам'ять кроку), після 3-го — на межі кроку ревізія → ранковий звіт → стоп (`NIGHT_SHIFT.md` §3). Раніше за ліком — якщо рядок «стиснення N» у самері показав втрату (два поспіль — ще й межу вгору, В-351). Число — ставка з даних однієї сесії; переглянути, коли в самері набереться ≥ 5 рядків «стиснення N». <!-- copy-ok: дім нічного порогу — NIGHT_SHIFT.md §3 -->
- **Стиснення — автоматичне, без ритуалу** (Konst EquipLens S40, 21.11.2026: «дочекаємося автостиснення… кожного разу вручну — інколи дратує»): на порозі ревізії агент робить ревізію (усе в коміти, самері §0) і **не просить `/compact`** — чекає автостиснення Claude Code; у маркері досить відсотка. Пропозиція `/compact` — лише коли Konst сам питає.
- **Модель і контекст — заміряні:** `get_session` (без `session_id`) → `session_context.model` · `effort_level`; контекст — рядок `ctx_watch` у контексті кожного повідомлення Konst (з журналу сесії; руками — `python3 <ядро>/tools/claude-code/hooks/ctx_watch.py line`).
- **Інша модель** — правило в профілі («ІНША МОДЕЛЬ»); без `--model` CLI бере своє замовчування — Opus 5.5 на підписці й API ( code.claude.com/docs/en/model-config, 07.11.2026).
- **Велике джерело — за типом задачі; Haiku шукає, я судю** (Konst EquipLens S40, 21.11.2026; поріг — Konst 24.11). Мірки (замір 24.11, haiku): український текст ядра — **3,4 байта на токен**; Read віддає ≤ 25 тис. токенів за виклик (≈ 84 КБ; `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS`, issue claude-code 15687 · 40357, 24.11.2026); податок старту субагента ≈ 35 тис. (`MODELS.md`). Файл > 30 КБ (≈ 9 тис.) цілком — нагадує `rules-guard`; далі за задачею: **(1) огляд цілого** (знайти все про X, інвентар, кандидати, перенос дослівно) → Haiku-карта: `рядок + дослівна цитата` → звірка грепом → читаю лише свої місця (пілот 24.11: 2 твердження «вже є в шапці» хибні — карта, не вирок); **(2) правка відомого місця** → grep + offset/limit, без Haiku; **(3) рішення від точного тексту** (правило, аудит, логіка документа) → читаю сам, частинами — Konst 24.11: «документ може бути ідеальним, але прочитаний неповно — примарні помилки». Дослівний перенос: `claude -p --model haiku --effort medium --tools "" --output-format json < запит` (правила «дослівно» + завдання + файл; > 100 тис. токенів — ріж) → `extract_check.py` = 100 % → 2–3 місця сам. Haiku читає у своєму контексті — у мій лише відповідь (GlassKit: 216 тис. токенів за $0.265; сам — ≈$0.86 і не вмістилось би: `EquipLens:archive/summaries/EquipLens_session_summary_S40_BG.md` §1 рядок 43). Нагадує `rules-guard`.
- **Effort** — правило в профілі («ЦИКЛ» п. 5); субагент і `claude -p` — effort явно, замовчування medium, low — лише механіка (Konst 24.11); на Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1 і новіших з підпискою чи API-ключем зміна effort кеш не скидає (не на Bedrock / Google Cloud / Claude apps gateway, не з `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` чи HIPAA; code.claude.com/docs/en/prompt-caching, 12.11.2026; `REPO_FRAME.md` §11).
- **Аудит правил:** клас правки → проходи, пакетом перед самері; нова модель Claude — лише файли класу 2; раз на 30 днів — `CLAUDE.md` репо (формула — `tools/claude-code/templates/AUDIT_template.md` «Коли і скільки»). Що застосовувати — профіль «АУДИТ ПРАВИЛ».

### Код, прилади, документація, інтерфейс

- **Хід, що міняє вигляд екрана** (заголовок, підпис, перемикач, `data-*`) — ДО повного прогону греп приладів продукту (`tools/stand/**` тощо) за **текстами й селекторами, які зникли**, не лише за іменами полів (AE S133: прилади чекали старого заголовка й перемикача).
- **Команду, яку заблокував гачок PreToolUse, не виконано цілою** — і `git checkout -b`, і правки в ній; перед комітом — `git branch --show-current`, після відмови — повторити потрібні частини окремо (AE S133: гілку не створено → коміт ліг у локальний `main`). Позначку огляду (`ui-review-gate.sh done`) і коміт — різними командами.
- **Прилад, що читає живі дані, ламається від роботи людини** (AE S133) — очікування пишуться ознаками (порядок за ключем, «довша — лише довга назва»), а стан — у фікстурі (пастка 8 — `kernel/wsd/Lens_patch_check_protocol.md`).
- **`CLAUDE.md` — до 20 тис. знаків, не лише до 200 рядків** (AE S134, пропуск Konst: 120 рядків, але 33 тис. знаків — рядок-абзац, мірка рядками мовчала; `doc_health` M1 тепер міряє й знаки): довідка, потрібна лише біля своїх файлів (команди гейтів, деталі воркера), — у `.claude/rules/<тема>.md` з `paths:`; у `CLAUDE.md` — суть і вказівник. Проба AE S134 (хмарна сесія з кількома репо, робоча тека `/home/user`): правило з `paths:` у репо-підтеці приходить після читання файла під своїм шляхом і не приходить поза ним (code.claude.com/docs/en/memory, 07.11.2026). Прилад, що звіряє перелік із `CLAUDE.md`, — читати й правило (AE `tools/gate_doc_v1.py`).
- **Даних нема в HTML сторінки — шукай, звідки сторінка їх бере** (AE S134): Playwright `page.on('response')` + клік вкладки → адреса джерела; брати основне джерело, запасне — лише коли основне порожнє; API з «?» в адресі — лише якщо `robots.txt` дозволяє (zenrows.com «Intercepting XHR Requests» · scrape.do, 05.2026). Дані для приладу-випадку — `.txt`, не `.html`: огляд UI бачить `.html` скрізь (хибне AE S134).
- **Сторінку документації — `curl` як `.md` і греп, не цілою в контекст** (FAB-1, 10.11.2026): інструмент читання сторінок на великій сторінці віддає весь текст (три сторінки code.claude.com — ≈ 40 тис. токенів); `curl -s https://code.claude.com/docs/en/<сторінка>.md > <скретчпад>/x.md` і `grep -n` — у контекст лише потрібний розділ (так прочитано решту 9 сторінок).
- **Перед пропозицією нової дії чи кнопки — перевір, чи вона вже є** (AE S139, знайшов Konst): греп назв дії в коді (`Видалити`, `pick`, `data-*`) + обхід екрана в стані з вибраним елементом (інспектор, меню «⋯»); у пропозиції — рядок «наявне: …» з доказом.
- **Смуга-повідомлення під шапкою — посередині між сусідами** (AE S139, пропуск Konst): у сітці шапки з `row-gap:0` відступ мають лише нижні сусіди → смуга «тулиться» до верхнього (заміряно 0 ⟂ 10 px); відступ — на самій смузі, рівний нижньому; сторож — замір «зверху = знизу ± 2 px» (AE `olya_walk` 33-д).

### Ревізія → `/compact`, поки кеш теплий

- **(а) Коли робити ревізію самому** (`/compact` не просити — чекати автостиснення, пункт «Стиснення — автоматичне» вище) (Konst AE S140; дірки першої редакції — `AE-Simulator:docs/fab/FAB2_compact.md`): стиснення переказує розмову — що не в репо, те губиться; тому спершу ревізія (усе з чату — у доми, самері §0 і стартове — «як є»), потім стиснення — автоматичне (`/compact` — рішення Konst). Дорого не читати великий контекст (з кешу — копійки), а **дати йому охолонути**: перший запит після паузи > 1 год пише всю розмову в кеш наново за подвійною ціною входу. Ревізію робити самому — у тій самій відповіді, що закриває предмет (її кінець і є початок можливої паузи): контекст ≥ 250 тис. токенів — на межі предмета, **на порозі ревізії — одразу**: поріг ревізії = поріг автостиснення − найбільший крок сесії (≥ 55 тис.) − 25 тис. на саму ревізію (AE S145, В-373: було 15 — заміряно ≥ 24 тис., ревізія з ✗ не встигла до автостиснення); при межі 450 тис. — ≈ 315 тис. (AE S141, В-352). Лічить програма — `hooks/ctx_watch.py` з журналу сесії (рядки ⓘ / ⚠ на повідомлення Konst і після кожного `git commit`; `python3 tools/claude-code/hooks/ctx_watch.py line` — замір руками); `get_session` → `context_usage` для порогів не годиться — відстає (AE S141);
  - вікну ліміту **не вистачить на наступний крок і саму ревізію**: залишок < 1,5 × ціна кроку + ціна ревізії (ціна — різниця замірів `list_events` → `unifiedWindows.<вікно>.utilization` до й після; AE S141: важкий крок ≈ 9 % п'ятигодинного → спрацьовує ≈ на 0,85; та сама формула, що вночі, `NIGHT_SHIFT.md` §3). Причина — **не пауза**: пауза Konst буває на будь-якому рівні ліміту, і від неї береже інше — коміт після кожного кроку (гачок `handoff-remind` після кожного коміту кладе нові ✗ / ⚠ `handoff_check` — пам'ять репо звіряється безперервно, не лише перед стисненням) і ⚠ «кеш холодний» `ctx_watch` на поверненні. Причина — що на нулі не пройде ні ревізія, ні `/compact`. Тижневе — та сама формула (крок ≈ 1 % тижня → лише ≈ 0,97); на перетині 0,85 тижневого — не ревізія, а один раз зміна плану (аудит — «тут · резервний · після скиду», нічна зміна — поріг 0,9) (Konst AE S141: «пауза може виникнути на будь-якому етапі ліміту» — В-354). Чому до охолодження: теплий кеш читається за 1/40 ціни входу на Fable 5.2 (на Opus 5.5 і Sonnet 5.5 — 1/20; platform.claude.com pricing, 12.11.2026), а холодний перший запит **переписує** всю розмову за подвійною ціною входу.
  - Кеш уже холодний (пауза > 1 год; на кредитах — > 5 хв): ревізію зроблено → нова сесія зі стартового, старий контекст не оплачується; ревізії нема → ревізія однаково (Konst 24.11: і на холодному кеші — щоб перед стисненням усе було в репо; `handoff_check` + таблиця) → рядок Konst «ревізію зроблено», `/compact` — рішення Konst. Ліміт вичерпано: `/compact` теж не пройде — тому ревізія на 0,85; тижневе вікно ≥ 0,9 → ревізія й стартове без `/compact`.
- **(б) Межа автостиснення і точка спрацювання.** **Межа автостиснення — 450 тис.** (вирок Konst AE S141, В-351): змінна середовища `CLAUDE_CODE_AUTO_COMPACT_WINDOW=450000` — одна на день і ніч; **ставить лише Konst руками** (меню середовища в заголовку сесії → Edit → Environment variables): `update_environment` її відхиляє як змінну, що керує сесією (заміряно AE S141, 12.11.2026) (змінна переважує `/autocompact`; вдень — страховка над порогом ревізії, вночі — дає роботі тривати). **Межа ≠ точка спрацювання:** стиснення спрацьовує на `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` % від (межа − 20 тис. на відповідь): у хмарі 92 ставить платформа сама (з заміру AE S141; документацією не підтверджено — code.claude.com/docs/en/model-config, 19.11.2026) → 0,92 × 430 тис. = **395 600** (звірено з `autocompact_state.threshold` на двох межах — 1 млн → 901 600 і 450 тис. → 395 600; AE S141). Діє з перезапуску процесу Claude Code в контейнері, не обов'язково з нової сесії (AE S141); `settings.json` репо в хмарній сесії з кількома репо, імовірно, не діє (тека сесії — не репо); фактична межа — `get_session` → `autocompact_state.threshold`; не вимикати (`DISABLE_AUTO_COMPACT` → сесія падає на межі контексту) (code.claude.com/docs/en/model-config «Set the auto-compact window», 12.11.2026). Якість після стиснення — рядок у самері «стиснення N: переказ ✓ / що загубив» (нагадує гачок старту з джерелом `compact`: «контекст N → M · наступне стиснення на … · ревізія на …»); два поспіль із втратами → межу вгору. **Після ручного `/compact` ходу агента нема** — команда локальна, модель чекає на повідомлення: Konst пише «далі» (будь-яке слово), і агент іде за самері; автоматичне стиснення посеред ходу роботу не зупиняє.
