| **Haiku 5.5** | лише субагент на **обмежену задачу з перевірним результатом**: пошук, витяг фактів, чернетки зі структурованого входу; у репо сама не пише | дешева; висновки — лише після перевірки Opus |

**Коли субагент узагалі вигідний — «податок холодного старту»** (здогадка Konst 07.10 — підтверджено заміром): кожен субагент / `claude -p` стартує з нуля і вантажить системний контекст Claude Code — **≈ 35 тис. токенів** на старт у нашому контейнері (замір вище: 1 183 вхід + 23 948 кеш-читання + 10 044 кеш-запис); стороннє вимірювання — ≈ 33 тис. на перший хід Claude Code (bestagent.dev, 2026; не першоджерело). Тому:
- **мала задача** (кілька файлів, одна відповідь) — робить головна модель сама: старт субагента дорожчий за саму роботу;
- **субагент** — коли (а) вивід великий і засмітив би головний контекст, або (б) роботу можна розпаралелити, або (в) потрібна незалежна друга думка;
- **багато субагентів паралельно** = багато холодних стартів; спільнота повідомляє про «у кілька разів більше токенів» і швидке вичерпання вікна лімітів (dev.to, zivtech, 2026 — не першоджерела) → не більше 2–3 без потреби;
- модель субагента **закріплювати явно** (`--model` / параметр `model` інструмента Agent): вбудований Explore, за повідомленнями, наслідує модель сесії, а не Haiku (code.claude.com/docs/en/sub-agents; github.com/anthropics/claude-code issue 29768 — перевірити своїм заміром).
- Вплив на вікно лімітів підписки напряму не міряється (`rate_limit_info` дає лише статус) — міряємо $ з `--output-format json` як замінник (зв'язок $ ↔ ліміти — не перевірено).

## Проба №1 — чернетка журналу самері (з еталоном) · переглянуто 07.10

Чому саме вона: Anthropic радить Haiku для підсумків, а самері тепер — **живий журнал** (профіль v13, `SUM-1`), рядок на кожен хід. Еталон — таблиця §1 `QR-Lens:archive/summaries/QR_Lens_session_summary_CC1_ADOPT.md` (≈ 35 рядків, Opus 07.10).
- **Вхід:** лише `git log` сесії CC-1 обох репо (повідомлення + `--stat`) і формат рядка (хід · коміт · суть · перевірка). Еталону модель не бачить.
- **Чесний еталон:** частина рядків §1 спирається на чат, а не на git log → перед пробою Opus позначає в еталоні лише факти, **виводимі з git log**; пропуски рахуються тільки по них.
- **Три руки:** Haiku 5.5 (effort low і medium) · **Sonnet 5.5** · Opus — еталон. Кожну — **2 прогони** (розкид).
- **Міра:** вигадки (коміт чи число, якого нема в git log) — **0**; пропуски ≤ 10 %; неправильні хеші/числа; $ і час з `--output-format json`; окремо — токени холодного старту.
- **Вирок:** найдешевша рука, що пройшла поріг, пише чернетки журналу; Opus звіряє й комітить. Не пройшла жодна — записати, де ламається.
