**Коли субагент узагалі вигідний — «податок холодного старту»** (здогадка Konst 07.10 — підтверджено заміром): кожен субагент / `claude -p` стартує з нуля і вантажить системний контекст Claude Code — **≈ 35 тис. токенів** на старт у нашому контейнері (замір вище: 1 183 вхід + 23 948 кеш-читання + 10 044 кеш-запис); стороннє вимірювання — ≈ 33 тис. на перший хід Claude Code (bestagent.dev, 2026; не першоджерело). Тому:
- **мала задача** (кілька файлів, одна відповідь) — робить головна модель сама: старт субагента дорожчий за саму роботу;
- **субагент** — коли (а) вивід великий і засмітив би головний контекст, або (б) роботу можна розпаралелити, або (в) потрібна незалежна друга думка;
- **багато субагентів паралельно** = багато холодних стартів; спільнота повідомляє про «у кілька разів більше токенів» і швидке вичерпання вікна лімітів (dev.to, zivtech, 2026 — не першоджерела) → не більше 2–3 без потреби;
- модель субагента **закріплювати явно** (`--model` / параметр `model` інструмента Agent): вбудований Explore, за повідомленнями, наслідує модель сесії, а не Haiku (code.claude.com/docs/en/sub-agents; github.com/anthropics/claude-code issue 29768 — перевірити своїм заміром).
- Вплив на вікно лімітів підписки напряму не міряється (`rate_limit_info` дає лише статус) — міряємо $ з `--output-format json` як замінник (зв'язок $ ↔ ліміти — не перевірено).

Ліки — повний шлях у запиті скрипта + перевірка рядка «Scope» у виводі (скрипт: ✗, коли «Scope» називає інший файл) — **правка скрипта після «так» Konst**.

**Еволюція — щоб аудит не стояв на місці:** кожен прохід Haiku — рядок у журналі аудиту з колонками «знайдено · підтверджено · хибних · нового, чого не бачили opus / sonnet». Перегляд **після 5 проходів** (агент сам, рядком у цьому файлі):
- нового справжнього ≥ 1 на 3 проходи **і** хибних ≤ 30 % → Haiku high — стандартний третій прохід для файлів із зовнішніми фактами (у формулу `templates/AUDIT_template.md` — правкою класу 1 після «так»);
- нового 0 за 5 проходів → прибрати з аудиту, лишити розвідку;
**Explore під Haiku:** вбудований розвідник Claude Code бере модель сесії; перемикання — файлом агента з `model: haiku` (Aivio — «user-level override»). У хмарному контейнері `~/.claude` одноразовий → лише файлом у репо (`.claude/agents/`) — окремою пропозицією, після заміру на нашій задачі.

## Метод «прохід на суперечності» — опція, не запроваджено (Konst 11.10.2026: «зафіксуй, підсиль»)

**Що.** Один прохід opus high на **кластер** файлів, що говорять про одне, з одним питанням: *де правило одного файла каже інакше, ніж правило іншого?* Не загальний аудит (його роблять окремі проходи), а лише суперечності.

**Навіщо.** Окремий прохід дивиться в один файл і суперечність з іншим файлом бачить лише випадково (A66 ⟂ A69 жила з 09.10 до 11.10, хоч обидва рецепти проходили аудит). Канон росте латками в різних файлах — суперечності накопичуються тихо, а агент, що прочитав один файл, діє за ним упевнено.

**Підсилення проти сирої ідеї** (замість «5 випадкових файлів у `/doctor`»):
1. **Кластер за темою, не випадковий набір:** рецепти однієї теми (A66 · A69 · A45 — тіні й теми), `CLOUDFLARE.md` + кукбук T13 (фільтр збірок), `CLAUDE.md` ядра + `PROFILE.md` + `templates/CLAUDE_template.md`, гачки + `CLAUDE_CODE.md` «Гачки». Суперечність живе між файлами про одне — там і шукати.
2. **Свій запит, не `/doctor prompt-audit`** (той скроєний під один файл і стиль): «Файли: … Знайди лише суперечності між ними. Для кожної — **дві цитати** `файл:рядок` (правило А · правило Б), чому несумісні, який новіший (`git log -1 --format=%cs -L`). Стиль, повтори без суперечності, історію — не звітувати. Нічого не правити.»
3. **Дві цитати — фільтр шуму:** знахідку без двох цитат агент відкидає, не звіряючи; з цитатами — звірка грепом за хвилину.
4. **Виняток ≠ суперечність:** вужчий файл може свідомо звужувати ширший (CLOUDFLARE «правка лише після так» ⟂ «знахідку — в ядро в тій самій сесії»). Такі — рядком «свідомий виняток» у вужчий файл, щоб наступний прохід їх не підняв.

**Як запускати** (коли дійде): `cd <ядро> && claude -p --model opus --effort high --output-format json "<запит з п.2>"` → звіт у `$AUDIT_OUT`; кожну знахідку — греп обох цитат; підтверджене — Konst «так» → правка; рядок у `kernel/Lens_AUDIT.md` з колонкою «проходи». Перед запуском — `get_session` → `rate_limit_info`, і названо в чаті: модель · effort · навіщо.

**Коли.** Раз на 30 днів разом із нагадуванням `env_check` про аудит `CLAUDE.md` — **один** кластер, де за місяць було найбільше комітів (`git log --since=30.days --name-only`); або після хвилі ≥ 5 комітів в одному кластері.

| плюси | мінуси |
|---|---|
| бачить суперечності між файлами, яких окремі проходи за будовою не бачать | **не замінює** окремі проходи: на вадах усередині файла — 3 з 10 (Проба №3) |
| дешево: ~$2 за кластер (замір 11.10: $2.05 за 5 файлів) | шум: у Пробі №3 усі 3 нові знахідки — низької впевненості; кожну звіряти |
| береже канон від тихого розходження, коли правила дописують латками в різних файлах | квота: тижневе вікно (11.10 — `allowed_warning`), тож лише за словом Konst, не автоматично |
| дві цитати роблять звірку механічною (греп), а не суперечкою | модель може читати журнали ядра й «впізнати» старі рішення — для тесту брати копію «до» (як Проба №3) |
| | частина «суперечностей» — свідомі винятки; без рядка-позначки вони повертатимуться щоразу |

**Правило прийняття.** Перший запуск — тест на кластері A66 · A69 · A45 (еталон відомий: A66a — справжня суперечність, обидві руки Проби №3 її знайшли). Поріг: знайдено A66a **і** хибних (без двох цитат або спростованих грепом) ≤ половини → метод живе, раз на місяць. Інакше — вирок «ні» з цифрами тут, як Проба №3.
