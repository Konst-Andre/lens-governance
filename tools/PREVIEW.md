# Прев'ю-стенд — репо `Konst-Andre/sandbox` (спільний для всіх Projects Konst)

> живе доки: існує репо `Konst-Andre/sandbox` з GitHub Pages. Змінився шлях прев'ю — правиться ЦЕЙ файл, Projects перечитують його адаптером (`tools/ADAPT.md`).
> дім: `lens-governance/tools/PREVIEW.md` · інструменти запису — `tools/CHAT_TOOLS.md`
> версія: 1.1 · 27.09.2026 · сесія LGH-3 · перенесено з `archive/superseded/Lens_github_push_protocol.md` §8 (О-5, ідея Konst G-X · форма G-Y 25.09.2026) + кроки «деплой зелений» і «промоція»
> Файл самодостатній: читається без знання Lens і без інших файлів цього репо, крім `tools/CHAT_TOOLS.md`.

## §1 Навіщо

Konst судить HTML (білд, мокап, стенд) **на пристрої** — з телефона чи ПК, за посиланням.
Репо продукту прев'ю не засмічують: там живе лише те, що пройшло вирок.
Тому прев'ю кладуться в окреме публічне репо `sandbox`, яке GitHub Pages віддає за адресою.

> Слово «пісочниця» в Lens зайняте (`kernel/Lens_sandbox_manifest.md` — копія білда із синтетичними даними).
> Репо `sandbox` у правилах зветься **прев'ю-стенд**.

## §2 Цикл: прев'ю → вирок → промоція

| # | крок | інструмент (`CHAT_TOOLS.md`) | детектор |
|---|---|---|---|
| 1 | Гейти проєкту на файлі зелені (валідатор · смоуки — що має Project) | контейнер | вивід гейтів у звіті ходу |
| 2 | Файл → `sandbox/<Проєкт>/<файл>_vN.html` одним комітом | квиток `put` → `gh_commit {blob}` з `expected_head` | `dry_run`: рядок `A`, не `M` |
| 3 | Дочекатись деплою Pages **саме цього коміту** | `gh_actions` → прогін `pages build and deployment` з SHA коміту = `success` | SHA прогону ≡ SHA коміту |
| 4 | У чат: посилання `https://konst-andre.github.io/sandbox/<Проєкт>/<файл>_vN.html` + SHA | — | посилання видано лише після кроку 3 |
| 5 | Вирок Konst | — | — |
| 6 | «так» → **промоція**: той самий вміст → живий файл у репо проєкту (шлях — з карти проєкту: `Lens_INDEX §5`, самері, README) одним комітом | `gh_commit {blob}` тим самим sha, що в кроці 2 | read-back: `git hash-object` живого ≡ sha прев'ю `vN` |

«Бай» (є правки) → нова версія `v(N+1)`, з кроку 1. Промоція не править файл дорогою: що судилось, те й живе.

## §3 Тверді правила

1. **Одне прев'ю = одна адреса.** Нова версія → новий `N`; наявний `_vN.html` не перезаписується.
2. **`<Проєкт>` = ім'я репо проєкту** (`EquipLens` · `QR-Lens` · `stock-check` · `Drive-Lens` · `AE-Simulator` …). Кожен Project — у своїй теці.
3. **Кореневий `index.html` sandbox не чіпається** — це стара вітрина AE-Simulator (S80–S83). Нові прев'ю AE теж ідуть у `AE-Simulator/`.
4. **Репо публічне:** лише те, що можна показати всім. Реальні дані клієнтів, аптек, людей — ні; синтетичні — так (рецепт — `Lens_sandbox_manifest.md`).
5. **Service worker у прев'ю не реєструється.** Реєстрація SW у файлі прев'ю вимкнена (закоментована з поміткою `PREVIEW`); при промоції — як у живому білді. *(Не перевірено, які білди реєструють SW — перевіряється на першому прев'ю кожного проєкту.)*
6. **Прев'ю — не канон.** Прополка `sandbox` — лише зі слова Konst.
7. **`sandbox/temp/`** — тимчасові файли Konst (не прев'ю, не вітрина). Агент їх не чіпає й туди не пише; прибирає лише Konst.
8. **Прев'ю з реальними даними — не сюди.** Сайт продукту живе на воркері Cloudflare → preview-адреса воркера `<аліас>-<воркер>.<субдомен>.workers.dev` (прод не змінюється; `lens-governance:tools/cloudflare/CLOUDFLARE.md` §2 п.13); увімкнення — «так» Konst. Сайт не на воркері → дані підміняються синтетичними **тієї ж довжини** (слово → вигадане слово стільки ж літер), щоб перенос і вилізання тексту були справжні (Konst 07.10.2026).

## §4 Чому саме так

**Кеш.** GitHub Pages віддає кожен файл із `Cache-Control: max-age=600` і змінити це не дає —
стару сторінку за тією самою адресою браузер може показувати до 10 хв
([issue blockdb #32](https://github.com/shivan2418/blockdb/issues/32), 09.2026 · [community #11884](https://github.com/orgs/community/discussions/11884)).
Перезапис однієї адреси = вирок не тій версії і зламане порівняння «було ⟂ стало». Адреса з версією — це і є версія.

**Деплой.** Коміт ≠ опубліковано: Pages збирається окремим прогоном. Посилання до зеленого прогону = «почекай хвилинку» і ризик вироку старій версії.

**Промоція тим самим вмістом.** Однаковий вміст дає однаковий `git hash-object` — рівність sha доводить, що в прод пішло рівно те, що бачив Konst.

## §5 Анти-приклади

- `sandbox` до G-Y: `index.html` переписувався щопрев'ю (`a15e3b2` → `d52160b`, п'ять комітів) — попередню версію видно лише в історії git, не за адресою.
- Посилання видане одразу після коміту, до деплою → Konst судить стару сторінку.
- При промоції «дрібно підправив» файл → у прод пішло те, чого ніхто не бачив.

## §6 Детектор (К2)

Read-back коміту в `sandbox`: рядок `M` на `*_v*.html` (перезапис версії) або будь-яка зміна кореневого `index.html` → ✗.
Промоція: sha живого файлу ≠ sha прев'ю, яке отримало «так» → ✗.
