# Адаптер — як канон доходить до інструкцій Projects (спільний для всіх Projects Konst)

> живе доки: у Konst більше одного Claude Project, що бере правила з цього репо. Змінився порядок адаптації — правиться ЦЕЙ файл; промпт §5 при цьому не міняється.
> дім: `lens-governance/tools/ADAPT.md` · канони, які він розносить, — реєстр §3
> версія: 1 · 27.09.2026 · сесія LGH-3 (слово Konst: «інструкції адаптивні, не один в один — щоб черпали джерело й адаптували»)
> Файл самодостатній: читається без знання Lens, `kernel/` чи будь-якого іншого файлу цього репо.

## §1 Патерн одним рядком

**Канон — один, в репо. Інструкції Projects — його адаптації, не копії.** Змінився канон →
Konst кидає в кожен Project один і той самий короткий промпт (§5) → агент того Project сам читає канон,
свою інструкцію й свій репо → видає в чат **повний** новий текст інструкції + «було → стало» → Konst вставляє сам.

| роль | що це | де живе |
|---|---|---|
| **канон** | самодостатні файли правил для всіх Projects | реєстр §3 |
| **адаптер** | цей файл: як адаптувати | `tools/ADAPT.md` |
| **промпт** | 6 рядків, що запускають адаптер; однаковий для всіх Projects і не старіє | §5 |
| **інструкція Project** | адаптація: лише те, що цьому Project треба щоходу, його мовою | поле Instructions (+ копія в репо Project, §4 п.7) |
| **паспорт адаптації** | рядок в інструкції: з яких версій канону зроблено | останній рядок інструкції (§4 п.6) |

Чому так: у Konst Projects різної природи — HTML-продукти, Excel-маршрути, документація. Правило,
яке одному потрібне щоходу, іншому — мертвий текст. Копія 1:1 або тягне зайве (агент виконує непотрібне
чи вчиться ігнорувати інструкцію), або розходиться з каноном мовчки.

## §2 Практика ззовні (мікроскоп форми, 27.09.2026)

**Kustomize — база + оверлеї** ([dev.to, «one base, every environment»](https://dev.to/secopsloghq/kustomize-bases-overlays-one-base-every-environment-2gim) · [OneUptime, 02.2026](https://oneuptime.com/blog/post/2026-02-09-kustomize-base-overlay-inheritance/view)).
- практика: одна база спільна; кожне середовище тримає лише свої відмінності, базу не копіює;
- беремо: канон = база, інструкція Project = оверлей; спільне не переписується в Project, а посилається;
- не беремо: машинне злиття — поле Instructions це текст для агента, «зливає» агент головою, а Konst судить результат.

**Copier — оновлення проєкту з шаблону** ([документація Copier, «Updating a project»](https://copier.readthedocs.io/en/stable/updating/)).
- практика: проєкт зберігає файл відповідей із версією шаблону, з якої його згенеровано; оновлення — дельта від тієї версії;
- беремо: **паспорт адаптації** — рядок з версіями канону в інструкції; наступна адаптація дивиться дельту канону, а не перечитує все наосліп;
- не беремо: автоматичний 3-way merge і CLI — у чату нема ні файлу-шаблону, ні git у полі Instructions.

## §3 Реєстр канонів

| файл | кому | що дає |
|---|---|---|
| `tools/CHAT_TOOLS.md` | **усім** Projects | конектор «Lens GitHub», квиток, правила запису, документи Project |
| `tools/PREVIEW.md` | Projects, що показують Konst HTML на пристрої (продукти, стенди, сайти) | прев'ю-стенд `sandbox`: прев'ю → деплой → посилання → вирок → промоція |
| `tools/ADAPT.md` | **усім** | цей файл |
| `kernel/**` (ядро Lens) | **лише** Projects сімейства Lens | стандарт роботи Lens. Іншим Projects не читати |

Новий спільний канон → рядок сюди в тому ж коміті. Немає рядка — адаптер його не розносить.

## §4 Правила адаптації (для агента Project)

1. **Читати мінімум:** цей файл · канони з §3, що стосуються цього Project · поточна інструкція (вона в контексті) · карта репо Project (`gh_list` кореня, README). Нічого іншого з `lens-governance`.
2. **Визначити природу Project** і назвати її першим рядком звіту: які репо, що виробляє (HTML · xlsx · документи · інше), як Konst перевіряє результат.
3. **Брати лише те, що потрібне щоходу.** Решта — посиланням на канон («деталі — `CHAT_TOOLS §2-б`»), не переказом. Переказ = друга копія, яка розійдеться.
4. **Прибрати мертве:** токени й способи запису через токен/REST (→ конектор), клон через токен (→ квиток `tar`), правила чужої природи (HTML-гейти в Excel-Project тощо), шляхи, яких у Project нема.
5. **Зберегти своє:** правила й патерни Project, яких канон не знає, лишаються — адаптер не стирає місцевого знання. Мова й терміни — Project'а.
6. **Паспорт адаптації** — останній рядок інструкції:
   `адаптовано з: CHAT_TOOLS v<N> · PREVIEW v<N> · ADAPT v<N> · <дата>` (лише ті канони, що взято).
   Наступний запуск: версія в паспорті = версія канону → «змін нема», текст не видається.
7. **Копія інструкції в репо Project.** Поле Instructions не версіонується й гине з Project. Якщо в репо Project ще нема файлу з текстом інструкції — запропонувати (дім і ім'я — за звичаєм цього репо), писати лише після «так».
8. **Видача:** повний текст одним code block, під ним «було → стало», далі блок «Від тебе» (що Konst має зробити руками). **У репо й документи Project — нічого до «так».**

## §5 Промпт (Konst копіює в новий чат потрібного Project)

```
Онови інструкцію цього Project за каноном.
1. Через конектор «Lens GitHub» прочитай Konst-Andre/lens-governance → tools/ADAPT.md
   і виконай його §4 для цього Project. Інші файли lens-governance — лише ті, що назве ADAPT §3.
   Не бачиш інструмента gh_read — скажи мені, і на цьому зупинись.
2. Видай мені ПОВНИЙ новий текст інструкції одним блоком, під ним — «було → стало» і «Від тебе».
   У репо й документи Project нічого не пиши, доки я не скажу «так».
```

Промпт не містить нічого, що старіє: що читати і як адаптувати — живе в §3–§4. Змінився порядок — правиться цей файл, промпт той самий.

## §6 Приклади й анти-приклади

**Приклад — Lens PWA, LGH-3 (27.09.2026).** Адаптація під конектор. Звірка з каноном інструкції
(`kernel/Lens_PROJECT_instruction.md`) знайшла три загублені рядки канону й токен у полі, якого в каноні вже не було.
Правило §2-Copier (паспорт) з'явилось саме звідси: без нього не видно, з якої версії поле розійшлось.

**Анти-приклад 1 — копія 1:1.** Інструкцію HTML-Project вставлено в Excel-Project: агент вимагає `--html`-гейт
для xlsx і «device-тест 1920/1536/1280» для таблиці маршрутів. Або виконує непотрібне, або вчиться пропускати інструкцію цілком.

**Анти-приклад 2 — секрет у полі.** Токен GitHub жив у полі Instructions Lens PWA після того, як канон його прибрав
(v3, 19.09.2026). Копія мовчки відстала від канону на тиждень; поле читає кожен чат Project.

**Анти-приклад 3 — «прочитай усе ядро».** Промпт адаптації, що веде агента в `kernel/` цілком: Project без Lens
тоне в чужому стандарті й переносить його правила до себе. Тому §3 — реєстр із колонкою «кому».

**Анти-приклад 4 — переказ замість посилання.** Рецепти `curl` скопійовано в інструкцію; канон виправив пастку,
інструкція — ні. Рецепт у каноні, в інструкції — «дослівно з `CHAT_TOOLS §2-б`».

**Анти-приклад 5 — запис без «так».** Агент «заодно» переписав файл у репо Project під час адаптації.
Адаптація лише видає текст; запис — окремий хід після слова Konst.

## §7 Детектор (К2)

- Інструкція Project без паспорта адаптації → адаптована до ADAPT v1 → запустити §5.
- Версія канону в паспорті < версії в шапці канону → запустити §5.
- В інструкції є рядок, схожий на токен (`github_pat_`, `ghp_`, ключ) → ✗, прибрати й сказати Konst: секрет під заміну.
