# Інструменти чату Claude — спільні для всіх Projects Konst

> живе доки: є хоч один інструмент чату нижче (конектор, документи Project). Змінився інструмент — правиться ЦЕЙ файл, Projects перечитують його одноразовим промптом (§5).
> дім: `lens-governance/tools/CHAT_TOOLS.md` · код інструментів — `tools/<імʼя>/` поруч
> версія: 1 · 26.09.2026 · сесія LGH-1
> Файл самодостатній: його можна читати без знання Lens, `kernel/`, cookbook чи будь-якого іншого файлу цього репо.

## §1 Що вміє чат (станом на 26.09.2026)

| Інструмент | Що дає | Де видно |
|---|---|---|
| Конектор **«Lens GitHub»** | читання й запис у будь-яке репо `Konst-Andre/*`: файли, коміти, гілки, GitHub Actions | у кожному чаті акаунта, в усіх Projects (підключений один раз, перевірив Konst 26.09) |
| **Документи Project** | агент сам читає, створює, замінює й видаляє доки свого Project | у чатах, привʼязаних до Project |

Код і технічний опис конектора: `tools/lens-gh/README.md`. Для роботи він не потрібен — достатньо цього файлу.

## §2 Конектор «Lens GitHub» — 6 інструментів

| Інструмент | Для чого |
|---|---|
| `gh_read` | прочитати файл; великі — діапазоном рядків `start_line`/`end_line` |
| `gh_list` | тека або все дерево репо (`recursive`) |
| `gh_log` | останні коміти гілки |
| `gh_commit` | **один коміт з багатьох змін**: `edits` (заміна фрагмента, `old` рівно 1 раз) · `content` (новий файл) · `content_base64` (бінарний) · `from`+`move` (перенести) · `delete`; `dry_run` |
| `gh_branch` | гілки: список · створити · видалити |
| `gh_actions` | workflow: список · прогони · кроки · лог · запуск · перезапуск · скасування |

## §3 Правила запису (для будь-якого Project)

1. **Спершу дивлюсь, потім пишу.** `gh_log` → голова гілки; читаю файли, які правлю.
2. **`dry_run` → план показано Konst → «так» → `gh_commit` з `expected_head`** (sha голови, яку я бачив). Без `expected_head` конектор запис у наявну гілку відхиляє; зрушила гілка — перечитати й повторити.
3. **Один хід = один коміт** (може містити багато файлів). Правки — фрагментами (`edits`), не цілими файлами: дешевше й безпечніше.
4. **Після коміту — read-back:** перечитати записане й звірити.
5. **Гілки.** Працюємо в `main`, окремі гілки не заводимо без причини. Видалити гілку — лише на пряме слово Konst і після звірки, що в ній нема нічого, чого нема в `main`. `main` конектор не видалить ніколи.
6. **Токени й ключі — ніколи в тексті:** ні у файлах, ні в самері, ні в памʼяті, ні в репо (репо публічні). Токен GitHub живе в секреті воркера, тому в інструкції Project він не потрібен. Засвітився в чаті — сказати Konst: секрет під заміну.

## §4 Документи Project

- Агент **сам**, без нагадування, створює, замінює й видаляє доки свого Project.
- Роль Project: **незмінне** (що рідко змінюється) + **транспорт** (файл чекає, поки отримає дім у репо).
- Порядок транспорту: коміт у репо → read-back ≡ → **лише тоді** видалити з Project. У Project нема історії: видалене — назавжди.
- Кожна зміна доків Project скидає кеш усім чатам цього Project — писати пачкою, не чернетками.

## §5 Одноразовий промпт для іншого Project

Konst копіює текст нижче в новий чат потрібного Project (один раз і повторно — коли цей файл оновився):

```
Онови інструкцію цього Project під нові інструменти чату.
1. Через конектор «Lens GitHub» прочитай ОДИН файл: Konst-Andre/lens-governance → tools/CHAT_TOOLS.md.
   Нічого іншого з lens-governance не читай — ядро Lens цьому Project не потрібне.
   Не бачиш інструмента gh_read — скажи мені, і на цьому зупинись.
2. Прочитай поточну інструкцію цього Project (вона в тебе в контексті) і репо цього Project (назви, яке).
3. Адаптуй §2–§4 під цей Project: його репо, його патерни, його мову. Зайве для цього Project — прибери.
   Токени з інструкції прибери (конектору вони не потрібні); якщо інструкція згадує старий спосіб запису
   через токен/REST — заміни на конектор.
4. Видай мені ПОВНИЙ новий текст інструкції одним блоком, а під ним — список змін (було → стало).
   Я вставлю його сам. У репо й документи Project нічого не пиши, доки я не скажу «так».
```
