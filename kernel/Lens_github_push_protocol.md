# Lens · GITHUB-PUSH-ПРОТОКОЛ — запис у репо з чату Claude (П-GH1)

## §0 Що це і чому так
Claude у чаті (браузер, телефон) пише в GitHub **сам**, без Claude Code і без свого сервера:
контейнер чату ходить у `api.github.com` (домен дозволено), авторизація — fine-grained PAT.
Перевірено 16.09.2026 на AE-Simulator: гілка 201 → коміт 201 → читання назад → видалення гілки 204, `main` без змін.

Чому не конектор (звірено веб-пошуком 16.09.2026):
- офіційний віддалений GitHub MCP для Claude потребує OAuth через GitHub App — у claude.ai не підтримано (дока github-mcp-server);
- «Add custom connector» у claude.ai приймає лише OAuth, без Bearer/заголовків → свій сервер = свій OAuth-шар;
- Render free засинає після 15 хв (прокидання ~1 хв) → конектор падає на першому виклику.
Коли з'явиться офіційний конектор із записом — цей протокол у `archive/superseded`.

## §1 Токен (робить Konst, ~3 хв, на ПК)
1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate.
2. Repository access → **Only select** → потрібні репо (зараз: AE-Simulator, lens-governance).
3. Permissions → Repository → **Contents: Read and write**. Більше нічого.
4. Expiration ≤ 30 днів. Дата — в імені токена (`claude-github-exp-РРРР-ММ-ДД`).

Токен належить **GitHub-акаунту**, не акаунту Claude → **один токен працює в обох акаунтах Claude**.

## §2 Де живе токен
**Тільки в інструкції Project** (кожного акаунта Claude, де потрібен запис). Ніде більше:
не у файлах Project, не в самері, не в пам'яті, **не в репо** (репо публічні).
Скрипт додатково блокує коміт, у якому є рядок, схожий на токен.

Місце в інструкції: **окремим блоком одразу після «ДЖЕРЕЛА ПРАВДИ»**, до «СТАРТ СЕСІЇ».
Порядок технічно не критичний (інструкцію видно цілком), але заборона, що стоїть вгорі,
читається раніше за будь-яку дію старту.

## §3 ЗАПОБІЖНИК — чотири шари
| шар | що | тип |
|---|---|---|
| **Ш1 Права токена** | лише Contents RW на вибрані репо: не може видалити репо, змінити налаштування, додати людей | жорсткий (GitHub) |
| **Ш2 Правило П-GH1** | без явного «так» Konst **у поточному чаті** — жодного запису | процедурний |
| **Ш3 Скрипт** | двоходовий PLAN-ID: запис неможливий без попереднього показаного dry-run; видалення файлу — лише `--delete` у тому ж PLAN-ID (шлях існує в базі, у dry-run рядок ВИДАЛЕННЯ); видалень гілок і force-push немає | технічний |
| **Ш4 (опційно) Ruleset на `main`** | GitHub → репо → Settings → Rules → заборонити deletion і force-push для `main` | жорсткий (GitHub) |

⚠ Чесно: Ш2–Ш3 тримаються на дисципліні Claude — модель технічно могла б викликати API в обхід скрипта.
Тому жорсткі межі — Ш1 і Ш4. **Вимикач:** прибрати рядок `GH_TOKEN` з інструкції → запис неможливий взагалі.

## §4 П-GH1 — правило повним текстом
> **П-GH1 (запис у GitHub з чату).** Claude пише в GitHub лише через `Lens_claude_github_push.py`
> (тягне його raw щосесії, як `Lens_validate.py`). Жодного запису на старті сесії, «заодно» чи з власної ініціативи.
> Кожен запис — окремий хід за циклом wsd: **мікроскоп пушу** (репо · гілка · кожен файл: НОВИЙ/ЗМІНА +/− · PLAN-ID з dry-run)
> → явне «так» Konst у цьому чаті → `--confirm PLAN-ID`. Питання «пушимо?» — завжди окремим віджетом, не приховано в тексті.
> Типова ціль — нова гілка; `main` — тільки коли Konst назвав саме main.
> Видалення файлу — лише `--delete` під PLAN-ID, коли Konst у цьому чаті назвав **конкретний шлях**
> (загальне «видаляй, що треба» не рахується); у мікроскопі пушу — окремим рядком ВИДАЛЕННЯ.
> Видалення гілок і force-push — лише руками Konst на GitHub.
> Заборон шляху немає: В-31/В-94 скасовано В-139 (AE S82) — репо є єдиним домом продукту. Токен — лише в інструкції Project; у файли, самері, пам'ять, репо — ніколи.
> Токен прострочився (401) → сказати Konst, нічого не обходити.

## §5 Сценарій ходу (для Claude)
```
curl -sO https://raw.githubusercontent.com/Konst-Andre/lens-governance/main/kernel/Lens_claude_github_push.py
export GH_TOKEN='<з інструкції Project>'
python3 Lens_claude_github_push.py --repo Konst-Andre/<репо> --branch <гілка> \
   --message "<що і чому>" --dry-run  <шлях/в/репо>=<локальний файл> ...
# → мікроскоп пушу з виводу + віджет «Пушимо? PLAN-ID xxxxxx» → чекати «так»
python3 Lens_claude_github_push.py ...той самий виклик... --confirm xxxxxx
```
**Кінець ходу пушу (wsd `1.14`).** `--gov` — до dry-run, на локальному стані, що йде
в коміт; підсумок ✓/⚠/✗ і дельта — у `--message`. Після `--confirm`, у тому ж ході:
read-back кожного файла з репо, md5 = локальний; розбіжність → стоп і звіт.
Без read-back пуш не завершений.

**Хибний ✗ у read-back (Ф-22, G-N 18.09.2026).** `bash_tool` виконує `sh`: `{a,b}` не розгортається,
`cmp` отримує неіснуючий шлях → «N/M» на правильному коміті. Read-back — через `bash -c '…'` або
з повним переліком шляхів; кирилицю й діфи гейта — через `python3` (`difflib`), не `diff | grep`.
Read-back «N/M» з N < M перед будь-якою дією повторюється з друком кожного шляху й md5 обох сторін;
шлях, якого немає з обох боків, — помилка команди, не коміту. Хибний ✗ тут шкідливіший за відсутній:
він штовхає «виправляти» правильний стан.

Мердж гілки в `main` — кнопкою Konst на GitHub або окремим «так, у main» (тоді новий dry-run з `--main`).

## §8 Прев'ю-стенд — `Konst-Andre/sandbox` (О-5, ідея Konst G-X · форма ухвалена G-Y 25.09.2026)

> Слово «пісочниця» зайняте `Lens_sandbox_manifest.md` (копія білда із синтетичними даними).
> Репо `sandbox` у правилах зветься **прев'ю-стенд**.

**Тригер.** Є HTML (прев'ю білда, мокап, стенд), який Konst має побачити на пристрої до вироку.

**Дія.** Новий файл у `Konst-Andre/sandbox` за шляхом `<Продукт>/<файл>_vN.html`
(`<Продукт>` = ім'я продуктового репо: `EquipLens` · `QR-Lens` · `stock-check` · `Drive-Lens`).
**Одне прев'ю = одна адреса:** нова версія → новий `N`; наявний файл не перезаписується.
Адреса для Konst: `https://konst-andre.github.io/sandbox/<Продукт>/<файл>_vN.html` — у відповіді разом із SHA коміту.
Корінь `index.html` не чіпається: це вітрина AE-Simulator (S80–S83).
Репо публічне → кладеться лише те, що можна показати публічно (синтетичні дані — `Lens_sandbox_manifest.md`).
Прев'ю — не канон: живий білд і стенди лишаються в репо продукту; прополка `sandbox` — лише зі слова Konst.

**Чому.** Перезапис однієї адреси (`index.html`) ламає порівняння «було ⟂ стало» і дає вирок не тій версії:
кеш Pages і service worker віддають стару сторінку під тією самою адресою. Адреса з версією — це і є версія.

**Анти-приклад.** `sandbox` до G-Y: `index.html` переписувався щопрев'ю (`a15e3b2` → `d52160b`, п'ять комітів);
попередню версію видно лише в історії git, не за адресою.

**Детектор (К2).** Read-back коміту в `sandbox`: `git diff --name-status <SHA>^ <SHA>` — рядок `M` на
`*_v*.html` (перезапис версії) або будь-яка зміна кореневого `index.html` з Lens-сесії → ✗.
