## Чому саме така структура

**Порядок блоків = порядок застосування.** Читання → де правда → де токен → як працюємо →
скільки контексту лишилось → куди зберігати → як заводити нове → чим перевіряти.

**Числа бази — у §5 самері, не тут.** Після кожної governance-сесії HEAD, md5 Lens_validate,
розміри файлів міняються. Hardcode в інструкції старіє мовчки й стає бомбою на старті
наступної сесії: clone не збігається — «розібратись до роботи» — витрачено перший хід.

**Токен — у повідомленні, не у файлі.** Файл Instructions лежить у двох і більше Project
одночасно, Project підключені до публічних репо. Токен у файлі = витік у кожен з них.
Практика: одне коротке повідомлення «Токен: github_pat_…» на початку governance-сесії,
більше нічого не змінюється.

**gov-protocol у НЕ ЧИТАТИ тільки у продуктовій сесії.** Governance-сесія без протоколу —
наосліп: не знаєш ні черг, ні стелі, ні процедури перевірки. v2 забороняв читати завжди —
помилка, виявлена і виправлена G-S 19.09.2026.
