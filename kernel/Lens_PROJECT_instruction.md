# Інструкція Project — готовий текст на заміну

**Що робити:** відкрити Project → Instructions → **видалити весь поточний текст** → вставити блок нижче.

## Версія для змішаного Project (поточний стан — усі продукти в одній теці)

```
Мова спілкування — українська.

СТАРТ СЕСІЇ — читати в цьому порядку (wsd 1.1):
1. Lens_INDEX.md — маршрутизатор бази знань, ЗАВЖДИ першим
2. останнє <Product>_session_summary_*.md — контекст попередньої сесії
3. Work_Standard.md (wsd) — протокол, цілком
4. Lens_iOS_cookbook.md — точково за індексом, якщо задача торкається iOS/PWA/UI
Work_Standard_HISTORY.md на старті НЕ читати — тільки коли правило посилається на 14.x.

МАРКЕР НАВАНТАЖЕННЯ ЧАТУ — жорстко останнім рядком КОЖНОЇ відповіді (wsd 1.2),
і дубльований у полі question віджета ask_user_input_v0:
  <70%    — короткий маркер стану
  ~70-85% — маркер + пропозиція зробити [!самері]
  ~85%+   — САМ роблю [!самері] файлом, без запиту, + оголошую переїзд у новий чат

РОБОЧА КОПІЯ — усе, що будується в сесії (preview HTML, патч, самері), одразу
зберігати в /mnt/user-data/outputs з версією в імені (wsd 1.6 / 10.7).

НОВИЙ ФАЙЛ — обов'язково з рядком «живе доки: …» у шапці (wsd 1.8).
НОВИЙ ЗАПИС — спершу визначити дім за таблицею чотирьох ролей (wsd 12.11),
потім писати. Запис без названого дому = не записаний.

ПЕРЕД ВИДАЧЕЮ — прогнати гейти: python3 Lens_validate.py --html <файл>
Після governance-правок — python3 Lens_validate.py --gov .

Усе інше — форма правил (К1/К2), самері, віджети, compare-раунди, device-арбітр,
стиль пояснень — канонічно живе у Work_Standard.md і Lens_PROFILE.md. Тут НЕ дублювати.
```

## Що змінилось проти поточної інструкції — і чому

| було | стало | причина |
|---|---|---|
| «прочитай wsd + Cookbook + останнє самері» | **`Lens_INDEX.md` першим**, HISTORY явно виключено зі старту | старий порядок = 181 KB наосліп, щоб дізнатись, які файли існують (wsd 1.1) |
| Cookbook «фактично читати щоразу» | точково за індексом | 227 KB щосесії — це не вибірковість, а звичка. Точковий греп дешевший і не витісняє контекст задачі |
| — | **рядок «живе доки»** у кожному новому файлі | wsd 1.8; без нього тека росте монотонно |
| — | **маршрутизація перед записом** (12.11) | інакше знахідка лишається в тілі самері й помирає разом із ним |
| — | **гейти `Lens_validate.py`** | wsd К2: правило без детектора провалюється тихо |
| «Усе інше канонічно живе у wsd» | «…у wsd **і `Lens_PROFILE.md`**» | пам'ять не переноситься між Projects; профіль тепер має файловий дім |

**Що свідомо лишено як було:** блок маркера навантаження (дубльований навмисно — це
механічне правило, яке найчастіше злітає, і воно варте дубля) і рядок про робочу копію
в `/mnt/user-data/outputs` (контейнер справді скидається; ціна нагадування нульова).

**Що прибрано:** перелік конкретних файлів по іменах. Він протухає щоразу, коли файл
перейменовується чи ділиться, і саме це щойно сталось з `wsd_TODO_running.md`.
Тепер інструкція називає **індекс**, а індекс називає файли — одне місце правки замість двох.
