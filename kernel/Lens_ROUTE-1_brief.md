## §5 Кроки

**Практика ззовні (22.11.2026):**
- **Spec-driven development для агентів (пошук 22.11.2026):** робочий файл кроків (`tasks.md` / `roadmap.md`), кожен пункт — перевірювана дія; зміна вимог — спершу файл, потім код; без файлу вимоги «розсипаються по історії чату» ([Vercel «Spec-driven development»](https://vercel.com/i/spec-driven-development) · [JetBrains Junie, 10.2025](https://blog.jetbrains.com/junie/2025/10/how-to-use-a-spec-driven-approach-for-coding-with-ai/) · [Addy Osmani «How to write a good spec for AI agents»](https://addyosmani.com/blog/good-spec/)). **Беремо:** таблицю кроків з умовою готовності; «спершу карта, потім код». **Не беремо:** три окремі файли requirements / design / tasks — у Lens це вже бриф + черга; доказів, що SDD зменшує дрейф, джерела не дають (Taskade 2026: частина інженерів відмовилась) — тому міряємо самі (крок 4).
- **Керування змінами обсягу (пошук 22.11.2026):** базова лінія + реєстр запитів у три стадії «подано → оцінено вплив → рішення», з «хто, коли, чому», щоб не сперечатись удруге; «стоянка» (parking lot) для добрих ідей не про поточну мету, з оглядом за розкладом ([Atlassian «Scope creep»](https://www.atlassian.com/work-management/project-management/scope-creep) · [ProdPad «Scope creep»](https://www.prodpad.com/glossary/scope-creep/) · [Built In, 13 команд](https://builtin.com/software-engineering-perspectives/scope-creep)). **Беремо:** «вхідні» = подано + рішення в тому ж ході; «зміни маршруту» = реєстр з причиною; огляд стоянки — на межі етапу, не раз на два місяці (наш темп — етап за дні). **Не беремо:** формальний запит на зміну з погодженням — у нас один власник, Konst; його слово і є рішенням, машина лише не дає йому загубитись.

**Кроки (кожен — хід і коміт):**
1. **`tools/claude-code/route_check.py`** (ядро, без залежностей) — читає таблицю карти з черги продукту (шлях — `--queue`, типово перший `*CHERGA*.md`; розділ — заголовок з «карта кроків»). **✗:** крок ▶ не рівно один · крок без «готово, коли» чи «далі» · «далі» веде на неіснуючий крок. **⚠:** самері §0 (найновіше) чи черга §0 «Зараз» не називають крок ▶ · рядок «вхідні» без «→ куди» · крок ✅ без дати. **ⓘ дрейф:** коміти сесії з id кроку ▶ у повідомленні ⟂ без нього (`git log` від старту сесії; лише рахунок, без судження). `line` — рядок для звіту: `маршрут: ▶ Ф3-1г · далі Ф3-1д · вхідних нерозібраних 0 · за сесію комітів по кроку 3 з 7`. `selftest` + `--inject` (два ▶ → ✗; «далі» на неіснуючий → ✗).
2. **`route-remind`** — маршрут бере з `route_check line` (є карта) і лише тоді з «МАРШРУТ» самері (старі репо); у тексті нагадування — «рядок машини як є». Plus «вхідні»: Konst пише нове («додай», «ще», «знайшов», «хочу», «а давай», посилання чи знімок) → у контекст: «розклади нове з цього повідомлення у вхідні карти тим самим ходом: у крок X · новий крок після Y · стоянка до етапу Z · ні — чому». Хибні — журнал гачків.
3. **`handoff_check revision` (18)** — той самий `route_check` у ревізії; печатка ревізії несе «маршрут ✓ / ⚠ N».
4. **Пілот EquipLens ≥ 3 сесії** → §7: скільки ⚠ справжні, чи зменшились пропуски Konst класу «маршрут не назвав», чи Konst каже «бачу, куди йдемо». Тоді — рядок у `tools/claude-code/templates/` (шаблон черги з розділом карти) і в `ADOPT.md`.

**Другий погляд (22.11.2026):**
- **третій шлях:** не новий прилад, а нова перевірка всередині `handoff_check` — дешевше, але `handoff_check` біжить лише на ревізії й після коміту, а рядок маршруту потрібен щоходу в `route-remind` → окремий модуль, який кличуть обидва (одна правда, дві точки виклику).
- **премортем — через тиждень провалилось, бо:** (1) карта стала ще однією копією, що розходиться з брифом і самері → прилад звіряє §0 обох з ▶, а бриф тримає деталі без стану; (2) Konst вважає рядок «маршрут:» шумом → рядок один, без пояснень, і `route-remind` кладе його лише раз на три звіти чи на питання; (3) «вхідні» обростають і ніхто не розбирає → огляд стоянки — обов'язковий пункт на межі етапу (рядок у карті); (4) агент оновлює ▶ лише в таблиці, а не в самері → ⚠ (1) ловить; (5) регулярка «нове від Konst» шумить на кожне «так, додай» → ознака лише разом із чимось, що не відповідь на питання агента; поріг — за журналом першого тижня.
- **ціна для Konst:** ручних кроків нема; разово — прочитати карту EquipLens і сказати, чи порядок той (`Ф3-3` каркас двох табів перед аркушем «+» — моя зміна маршруту).
- **власні рішення:** антиприклад — Jira-дошка з сотнею карток (маршрут тоне в шумі) → у карті лише кроки поточного маршруту, решта — черга. Варіація — показувати карту Konst сторінкою (артефакт) з ▶ і ✅ → 💡, не тепер. Підсилення — у кожного кроку «далі» (слово Konst «доповнювали кожен крок виконаний іншим кроком»): прилад вимагає це полем, не звичкою.
- **неперевірене:** чи регулярка «нове від Konst» дасть менше 1 хибного на сесію — міряє пілот.
