## §5 Кроки

**Практика ззовні (22.11.2026):**
- **Spec-driven development для агентів (пошук 22.11.2026):** робочий файл кроків (`tasks.md` / `roadmap.md`), кожен пункт — перевірювана дія; зміна вимог — спершу файл, потім код; без файлу вимоги «розсипаються по історії чату» ([Vercel «Spec-driven development»](https://vercel.com/i/spec-driven-development) · [JetBrains Junie, 10.2025](https://blog.jetbrains.com/junie/2025/10/how-to-use-a-spec-driven-approach-for-coding-with-ai/) · [Addy Osmani «How to write a good spec for AI agents»](https://addyosmani.com/blog/good-spec/)). **Беремо:** таблицю кроків з умовою готовності; «спершу карта, потім код». **Не беремо:** три окремі файли requirements / design / tasks — у Lens це вже бриф + черга; доказів, що SDD зменшує дрейф, джерела не дають (Taskade 2026: частина інженерів відмовилась) — тому міряємо самі (крок 4).
- **Керування змінами обсягу (пошук 22.11.2026):** базова лінія + реєстр запитів у три стадії «подано → оцінено вплив → рішення», з «хто, коли, чому», щоб не сперечатись удруге; «стоянка» (parking lot) для добрих ідей не про поточну мету, з оглядом за розкладом ([Atlassian «Scope creep»](https://www.atlassian.com/work-management/project-management/scope-creep) · [ProdPad «Scope creep»](https://www.prodpad.com/glossary/scope-creep/) · [Built In, 13 команд](https://builtin.com/software-engineering-perspectives/scope-creep)). **Беремо:** «вхідні» = подано + рішення в тому ж ході; «зміни маршруту» = реєстр з причиною; огляд стоянки — на межі етапу, не раз на два місяці (наш темп — етап за дні). **Не беремо:** формальний запит на зміну з погодженням — у нас один власник, Konst; його слово і є рішенням, машина лише не дає йому загубитись.

## §5-б Синхронізація — один модуль, усі точки його кличуть (Konst 22.11: «щоб не було окремого інструменту, який не синхронізовано працює з… документацією, гачками, машинами… кожен доповнював та підсилював один одного… вияви дірки та вилікуй»)

**Принцип:** правда — лише таблиця карти в черзі продукту. `route_check.py` — єдиний, хто її читає; гачки, ревізія, іспит, старт сесії й сторінка беруть його вивід, а не читають карту самі (свій парсер у кожного = розсинхрон). Пише карту лише агент, тим самим комітом, що закриває крок.
