Поруч, без окремого шару: тести з першого дня (Chromium-поведінка, `ui_lint` стани, офлайн, зуби) · документи (карта дерева, рядок «Дизайн-основа») · ПК: те саме дерево + шар адаптивності (container queries, `pointer: fine` / `hover`), пристрій-арбітр — ПК.

Не беремо: Vite / Bun (npm і залежності), import maps багатьма файлами (офлайн лише з SW-кешем). Світ 18.10.2026: шари CSS — Dialtone, Panda CSS; import maps — без збірки, але офлайн — через кеш (preactjs.com, itnext.io); спрайт і доступність — 216digital, W3C csswg #6310; збирачі одного файла — vite-plugin-singlefile, Bun (мають npm).

**Рецепт ⟂ світ ⟂ замір → рішення:** рецепти (`A27` · `A55` · `A75` · `A85` · `A110` · `A111` · `A115`) — кожен розв'язує одну задачу в однофайловому QR, але **як модулі вони не оформлені**: код живе всередині одного HTML ~470 КБ (замір QR 18.10: білд 472 533 байт, сторінка з даними 2,6 МБ), рецепт дає фрагмент, а не файл дерева · світ — шари CSS і модулі як окремі файли (Dialtone, Panda CSS), вихід — один файл лише через збирач (vite-plugin-singlefile, Bun) · **рішення:** рецепти лишаються довідником «що робить модуль і чому», каркас дає їм дім у дереві (`src/services/<рецепт>.js`); де модуль у каркасі стане кращим за фрагмент рецепта — рецепт отримує посилання на модуль (оновлення рецепта — в К3 / К5).

**Кроки (ядро; кожен — хід і коміт):** К1 розвідка до кінця (збірка Python: як вставляти й мітити; спрайт; шари; бюджет) → бриф · К2 **урок і конспект Konst** + канон «tools/claude-code/PWA_FRAME.md» (поруч `REPO_FRAME.md`: каркас продукту, як той — каркас репо; ≤ 200 рядків, рецепти — вказівниками) · К3 заготовка `tools/claude-code/templates/pwa/` (дерево `src/`, `build.py` з `check` і `--inject`, шаблон тесту, рядок `env_check`) + selftest у ядрі (заготовка збирається в одну сторінку, офлайн ✓) · К4 `frame_check` / `ADOPT.md`: новий продукт з інтерфейсом без дерева → ⚠ (QR — виняток за рішенням Konst 18.10) · К5 **польова перевірка — EquipLens**: перша збірка зі стендів на каркасі, уроки → назад у `PWA_FRAME.md` (як `BRIEF-1` (г)).
**К1 — розвідка (18.10.2026, QR CC-18; «так» Konst — «роби все як запланував»):**
- **Шари CSS** `@layer` — iOS Safari 15.4+ (caniuse.com/css-cascade-layers, 18.10.2026) → беремо: порядок `reset, tokens, base, components, utilities` один раз на початку стилю; чужий CSS — у свій шар (нешарований стиль перебиває всі шари — Dialtone).
- **Адаптивність для ПК** — container queries, Safari 16+ (wwdcnotes WWDC22 10048; caniuse базової таблиці не діставав — «не перевірено» для iOS-рядка) → шар `components` з `@container`, не медіазапити екрана.
- **Токени** — формат обміну W3C DTCG 2025.10 стабільний (звіт спільноти, не стандарт; 28.10.2025), окремо — Resolver (теми світла / темна) → **не беремо зараз**: для одного продукту джерело — CSS custom properties; JSON DTCG — лише коли стенд (EquipLens) віддаватиме значення машинно (міст `valuesLOCK` → токени), тоді — перетворення в збірці.
- **Дані** — великий вшитий об'єкт JS парситься як код; `<script type="application/json">` + `JSON.parse` — швидше на холодному старті, правило з ~10 КБ (V8 «The cost of parsing JSON» goo.gle/json-parse-babel; Quip «Efficiently loading inlined JSON data» — 1830 → 1758 мс на 550 КБ) → **беремо**: дані — окремим JSON-блоком, ніколи не JS-літералом. Знахідка для QR (порожній кадр на відкритті, Konst 18.10) — окремим кроком із заміром, не перенос.
- **Спрайт іконок** — `<svg hidden>` з `<symbol>` на початку `<body>`, `<use href="#id">`; `currentColor`; декоративна — `aria-hidden`, дія лише з іконкою — `aria-label` на кнопці (216digital; W3C csswg #6310).
- **Збірка** — готові «один файл» (vite-plugin-singlefile, Bun standalone HTML) тягнуть npm → **свій `build.py`**: вставляє файли за мітками `<!--@src path-->`, лишає коментар-мітку джерела (налагодження «звідки рядок»), штампує версію (`VER-1`), `check` — зібране ≡ джерелам, `--inject` — зуби, звіт розміру по частинах (бюджет: HTML без даних ≤ ціль продукту; дані — окремо).
- **Відкрите для К3:** чи ділити JS на модулі в джерелах як ES-модулі (`import`) і склеювати збіркою, чи простими файлами-функціями в одному просторі — вирішити на заготовці замірами (розмір, читаність, як агент шукає).

- **N3 · Паритет тем** (visual regression light dark): у Chromatic «modes» — кожна тема з **окремою базою й окремим прийняттям** (chromatic.com «Story modes», 2026); у Playwright — окремий контекст `colorScheme: 'dark'` на тему, окремий знімок; емуляція media-запиту **не перемикає** власний перемикач теми застосунку (debbie.codes «Testing color mode»). Розрив: знімки не ловлять «токена нема в одній темі» — потрібна звірка обчислених кольорів. → дім: маніфест §8.15 + новий підпункт «паритет значень токенів».
- **N4 · Кольори** (OKLCH tokens dark mode P3): токени — CSS-змінні на `:root`, тема — перевизначення; у темній **тон (hue) тримати сталим, міняти світлоту** — HSL-інверсія «бруднить» жовтий і синій (pravinkumar.co «OKLCH… 2026»); OKLCH дає P3 на iPhone — з fallback sRGB. APCA — як додаткова міра, порогів джерелами не підтверджено → «не перевірено». → дім: новий підпункт маніфест §8.5 «важелі кольору — у OKLCH, тон ⟂ світлота окремими важелями».
- **N5 · Повзунки** (accessible range slider): ціль ≥ 44 px (дизайн-системи Schwab · Toyota; WCAG AA — 24), **невидима площа дотику** ширша за видимий бігунок; значення видно біля бігунка **і** поле числа для точного вводу; крок-snap для дискретних значень, без зайвих рисок на малому повзунку; подалі від країв екрана (системні жести) — setproduct «slider UI», Toyota DX playbook, 19.10.2026. → дім: маніфест §8.4 ергономіка + §8.5.
- **N6 · Панель важелів як інструмент** (Tweakpane Leva lil-gui): Tweakpane — підтримує мобільні; Leva — для React; lil-gui — заміна dat.gui (discourse.threejs.org); **експорт — один шлях, кнопка «скопіювати JSON», лише змінені значення**; панель — лише в dev-збірці (skills «tuning panel», 19.10.2026). Storybook: стан важелів — **в адресі** (`?args=`), безпечні символи; складні значення — примітивами + перетворення (storybook.js.org «args»). → дім: маніфест §8.13 паспорт (експорт лише змінених) + §3 п.13 ЛОК + §2 (стан у URL).
- **N7 · Anthropic — візуальний цикл** (Claude Code best practices visual): ціль-знімок → реалізація → знімок → порівняння → повтор, бо модель не бачить власного результату; знімати **лише елемент**, не всю сторінку; відгук — конкретний (відступ у px, вага шрифту), не «не так» (через вторинні джерела — claudecode101 «visual iteration», superdesign.dev; першоджерело anthropic.com — **звірити в Х5**). → дім: маніфест §8.18 + §8.1.
- **N8 · Сценарний прохід** (cognitive walkthrough): на кожному кроці задачі — «чи знатиме новачок, що робити, і чи побачить, що вийшло» (Wharton et al.; Spencer — дві питання); задача — конкретна, не «користуйся панеллю»; **два проходи** — за задачею, потім евристики (Sears «heuristic walkthrough», usabilitybok.org). → дім: маніфест §8.18.
