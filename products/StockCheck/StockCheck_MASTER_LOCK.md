## §10 · КОНТРАКТ ЕКСПОРТУ (b28, device✓ 01.08.2026)

**Формат — справжній .xlsx**, не CSV і не SpreadsheetML. Причина класу: CSV не несе
інформації про власний роздільник, його обирає програма адресата за системним
*List separator* → той самий файл коректний у нас і розсипаний у керівника.
Патерн: Cookbook **A80** · стиснення **A81**.

| параметр | значення |
|---|---|
| лист | **АП** |
| колонки | **15**, шапка звірена програмно проти оригіналу — збіг 1:1 |
| Excel-таблиця | так, стиль `TableStyleMedium7` (один атрибут) |
| формули N/O | зі **кешованим `<v>`** — в'ювери формул не рахують |
| рядків на аптеку | **усі 83 SKU**, порожньо де не заповнено |
| режими | **два**: FILL = 1 аптека · Home = аптеки з візитами |
| аптеки без візиту | не потрапляють **ніколи** |
| стиснення | `CompressionStream('deflate-raw')`, фолбек `store` |

**Мапінг колонок:** A–E ← `ph.px/area/city/addr/net` · F/G ← `vis.tier.oTC/iW`
(фолбек `ph.oTC/iW`) · H–K ← `s.n/s.c/s.k/s.p` · L ← `normOfVisit(vis,ph,s)` ·
M ← `vis.vals[s.k]` (порожньо якщо `undefined`) · N/O ← формули + кеш.

**Заміряно на девайсі (01.08.2026):** файл 10–16 КБ → deflate спрацював.
Store дав би ×8–9 — це **іменований симптом** гілки фолбеку, видимий без консолі.
Вигляд 1:1 з бланком на ПК і мобільному, попереджень немає.

⚠ **Межа формату:** xlsx не зберігає кольори вбудованих стилів таблиць — у файлі лише
ім'я стилю. Сторонні в'ювери (LibreOffice, в'ювер Claude) показують інший відтінок.
Оригінальний корпоративний файл поводиться так само. **Не дефект генератора.**

### hole #1 «Дуга / Винагорода» — **WONTFIX** (не «відкладено»)

Reorder-спуск картки в «Перенесені» + celebration-дуга на Home **не будуються**.

**Причина — спростування спеки реальним маршрутом.** Фактичний маршрут представника:
`Home → FILL → заповнив → 📋 → Excel → закрив`. На Home після переносу він **не повертається**;
наступного разу відкриває вже для іншої аптеки й одразу йде в пошук.

hole #1 склеїв **дві різні функції** в один артефакт, і reorder не обслуговує **жодну**:

| функція | вимагає | де живе зараз |
|---|---|---|
| гедонічна («зроблено») | око на екрані **в момент** події | ✅ `fireReward()` у FILL, ~8× за візит |
| «передано» | відгук на віддачу вмісту | ✅ handoff-sweep на 📋 (Cookbook **A82**) |
| інформаційна («аптеку закрито») | читабельність **пізніше** | ✅ статика §5.2 + бейдж `Історія · N` |

Гедонічну — глядача в момент показу немає; інформаційну — при наступному відкритті
картка вже стоїть статично.

**Чому WONTFIX, а не deferred:** відкладене повертається в чергу й повторно з'їдає сесію
на планування вже спростованої ідеї. Ціна помилкового повернення ≈2–3 сесії
(VT/FLIP + стенд + порт + device×3 + канон).

**Не чіпається:** `animRing()` + `ARC{floor:600,ceil:1600,exp:1}` · `fireReward()` +
MOTION reward LOCK v2 · статика §5.2.

### Service worker — **не заводиться**

Заміряно 08.2026: GitHub Pages `max-age=600`, кеш протухає сам за звичайного користування.
SW купував би вікно ≤10 хв ціною постійної складності. Розбір: Cookbook **A79** ·

## §13 · МЕРЕЖА ЯК ФІЛЬТР — Р-28…Р-37 (b32.0, device✓ 08.08.2026)

### Модель

- **Р-28 · Модель B.** Мережа — **фільтр поруч з областю й містом**, не область
  видимості. Дозволено стан «Всі мережі»; картка несе позначку мережі; експорт
  ріже за мережею. Закрито **без стенда**: аргументи логічні, не перцептивні
  (П-41 — стенд і пристрій такий клас не судять).
  *Підстава — пастка прихованого стану:* при моделі A активна мережа «Сіріус»,
  пошук аптеки АНЦ дає «нічого не знайдено» без пояснення. Фільтр, що мовчки
  ховає дані, читається як зламаний застосунок.
- **Р-33 · `NETS[]` живе в білді повним масивом** — увесь машинний зріз §7 реєстру,
  16 рядків `{net,label,slug,kind,origin}`. Тимчасова мапа `net→label` зараз плюс
  повний реєстр потім = рівно той дубль двох джерел правди, який забороняє wsd 1.10.
  `PLATE_BG` / `MONO_INK` / резолвер ассетів приходять у b32.1 разом із сіткою.
- **Р-37 · `S.net` персиститься (`farmstore_net`), `S.city` — ні.** Асиметрія свідома:
  мережа — фільтр рівня **області**, місто — рівня перегляду. Name-guard за `NETS`,
  той самий контракт, що B57 для області.

### Порядок відсіву

**`topMatch`: мережа → область → місто → пошук.** Гейт мережі стоїть **першим рядком**,
при `S.net=''` — no-op. Вкладення моделі при цьому лишається область→місто (М-9):
мережа тільки звужує, не замінює вісь.

**Прийнятий наслідок (О-42, дефолт до стенда О-20):** гейт проходить і через `counts()`,
тобто **лічильники чіпів рахуються ПІСЛЯ мережі**. Якщо стенд вирішить інакше — виноситься
окремою функцією в b32.1, не правкою `topMatch`.

### Порядок областей — `AREA_ORDER`

```js
const AREA_ORDER=['Дніпропетровська','Полтавська','Кіровоградська'];
```

**Оголошення, не евристика (wsd 1.10).** До b32.0 `AREAS` будувався порядком першої
появи в `PH` — і дефолтом ставала Полтавська (341 аптека) при 458 у Дніпропетровській.
Порядок появи — властивість вивантаження, яку ніхто не зобов'язувався зберігати.

**Область поза оголошенням** іде в хвіст (між собою — алфавіт `uk`) і сигналить
**тостом при init** (Р-36): на пристрої консолі немає (wsd 1.12), тож сигнал у
`console.warn` дорівнював би відсутності сигналу.

### Ім'я експорту й підпис зрізу

- **Р-29 · У режимі «Всі мережі» експорт — ОДИН файл.** КАМ розбере фільтрами;
  колонка `ph.net` у бланку вже є (5-та). Окремі файли на мережу не робимо.
- **Р-30 · Мітка мережі береться з ЕКСПОРТОВАНОГО СПИСКУ, не з фільтра.**
  Наслідок: аптека Факультету називається `Факультет-Фарм_…` **за побудовою**,
  а не «якщо оператор не забув перемкнути фільтр».

**Контракт `netScopeLabel(list)`** — єдине джерело мітки для **обох** споживачів
(ім'я файлу + підпис зрізу в UI експорту, М-18):

| вхід | вихід |
|---|---|
| рівно одна мережа у зрізі | її `label` із реєстру (`'мережа аптек 9-1-1'` → `Аптека 9-1-1`) |
| кілька мереж | `Всі мережі` |
| порожній зріз | `Всі мережі` — не належить жодній мережі, окремої гілки не заводимо |

**М-25 · один рядок на обидва споживачі, з пробілом.** Варіант «`Всі-мережі` у файлі,

одруківка, а пробіл в імені файлу вже живе там разом із ядром адреси
(`просп.Науки, 99`). Дві форми купували б консистентність, якої в цьому імені немає.

### Р-31 · Позначка мережі на картці — ТЕКСТ, не іконка

Замір: розкид чорнила **3.40×** (`MOYA_APTEKA` fill 0.150 ⟂ `ANC` 0.537). Знак із
заповненням 0.15 попросив `k=1.15`, щоб читатись на плиті 73px; на картці списку
місця ~20–24px. Іконка = **третій розмір ассета** → новий різ усіх 30 + гейт + колонка
в реєстрі. Текст цієї ціни не має. Показувати **лише в режимі «Всі»** — при обраній
мережі дублює `netBtn`. **Форма** (чіп `.tchip` ⟂ голий текст) відкрита → О-41;
**той самий вміст у рядку журналу** — окрема задача, О-43 (контейнер вужчий).

### Р-34…Р-36 · поверхні, що показують стан

- **Р-34 · `netBtn` читає живий стан:** `Всі мережі · N аптек` або `<label> · N аптек`,
  де `N = homeModel().filter(topMatch).length`. Кнопка не має стати мертвою (wsd 3.9),
  а обіцянка майбутнього («поки що єдина мережа») — це і є брехня, яку знімає Д-6.
- **Р-35 · `ver` при b32.0 не бампається** — `v2.24.0` лишається. Видимої для
  користувача зміни версії немає; wsd 10.6 вимагає `batch` + `date`, не `ver`.
- **Р-36** — див. «Порядок областей» вище.

## §14 · ЧІП ДЕЛЬТИ — симетричний, один семантичний важіль (b32.2, device✓ 13.08.2026)

> *Продуктова логіка, не матеріал: сюди, а не в `materiality_valuesLOCK`. Числа заміряні
> в `StockCheck_port_b32_2_s16_money_net.html` 13.08.2026, не перенесені зі стенда на віру.*

### 14.1 Правило показу — симетрія

`d = saved − norm`. Чіп рендериться, **коли `d ≠ 0`**, зі знаком `+` або `−`.

Раніше показувалась лише **недостача**. Тепер обидва боки: перевищення норми — така сама
подія обліку, як і недобір, і ховати її означало показувати оператору неповну картину
там, де він приймає рішення про замовлення.

**Два входи, одне визначення.** Умова живе у двох місцях і **мусить лишатись дзеркальною**:
- `dchipHtml(lv, saved, norm)` — рендер при побудові списку (якір ~р.3399);
- live-гілка перерахунку при зміні лічби (якір ~р.3500), із коментарем-дзеркалом у коді.

Розійдуться — чіп з'явиться при першому рендері й зникне при першій правці (або навпаки),
і баг читатиметься як «глюк вводу», а не як розсинхрон двох гілок.
`saved === undefined` → чіпа немає взагалі: це «ще не рахували», а не «нуль».

### 14.2 Колір — НЕ власний важіль (Г-6)

Чіп фарбується `var(--sig)`, який ставить контейнер `.row.lv-*` за рівнем.
**Власного колірного класу під стан перевищення чіп не отримує** — ні `.dchip.over`,
ні будь-якого іншого.

**Чому.** Рядок уже несе семантику рівня. Другий важіль на тій самій осі при наступній
зміні палітри розійдеться з першим **мовчки**: рядок стане одного кольору, чіп на ньому —
іншого, і жоден детектор цього не спіймає, бо обидва правила «валідні».
Через це зелений чіп оверстоку коштував **нуль рядків CSS**.

### 14.3 Геометрія — заміряно

| токен | значення |
|---|---|
| `--chSize` | 10.5 |
| `--chPadY` / `--chPadX` | 3 / 5.5 |
| `--chRad` | 9 |
| `--chOffX` / `--chOffY` | 6 / 6 *(винос за кут, `top`/`right` через `calc(… * -1px)`)* |
| `--chBorderInt` | 55 *(рамка = `--sig` 55%, тобто теж один важіль)* |

Фон — `var(--cardBg)`, щоб чіп читався на будь-якому рівні рядка без окремого набору тонів.

## §12 · ВІДКРИТЕ

### 🔴 Лічильник «Перенесені» ⟂ список — роздвоєння визначення (знайдено 01.08.2026)

**Симптом.** Фільтр показує «Перенесені 3», список порожній: «Нічого не знайдено».
Дзеркально: «Активні» рахує 44, список показує 47.

**Корінь — два різні визначення «перенесеної»:**

| хто | джерело | що вважає перенесеним |
|---|---|---|
| `counts()` → `phState(px)` | `e.visits[len-1]` | **останній візит будь-коли**, без дати |
| `renderHome()` → `homeModel()` | `todayVisit(px)` | **тільки сьогоднішній** візит |

`todayVisit()` віддає `null`, якщо `last.date !== today()`. Аптека, перенесена 2–3 дні тому:
лічильник її бачить, модель дає `state='new'` → падає в кошик активних → фільтр порожній.

**Побічно:** `lastTr` (дата останнього переносу) у `homeModel` обчислюється і **ніде
не вживається** — дані для «перенесено N днів тому» збираються і викидаються.

**Не фікс, а розвилка семантики** — рішення потрібне до коду. Деталі й варіанти:
самері сесії E. Пов'язана вимога Konst: доступ до **минулого** візиту для повторного
експорту й дозаповнення, **без** роздування Home.
