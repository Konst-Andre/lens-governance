## §3 РІШЕННЯ-1 · Node 3 (hole #1) → **WONTFIX**, не «відкладено»

**Що вирішено:** reorder-спуск картки в «Перенесені» + celebration-дуга на Home **не будуються**.

**Причина (спростування спеки реальним маршрутом, Konst):** фактичний маршрут —
`Home → FILL → заповнив → 📋 → Excel → закрив`. На Home після переносу представник
**не повертається**; наступного разу відкриває вже для іншої аптеки й одразу йде в пошук.

**Діагноз:** hole #1 склеїв **дві різні функції** в один артефакт.

| функція | вимагає | де | стан |
|---|---|---|---|
| гедонічна («зроблено») | око на екрані **в момент** події | 📋 → FILL | ✅ `fireReward()` per-brand, ~8× за візит |
| інформаційна («аптеку закрито») | читабельність **пізніше** | Home | ✅ §5.2 статика (dim + `✓✓` + trbadge + ринг) |

Reorder не обслуговує **жодну**: гедонічну — глядача в момент показу немає; інформаційну — при
наступному відкритті картка вже стоїть статично. Ціна відмови: ≈2–3 сесії (VT/FLIP + стенд + порт + device×3 + канон).

**⚠ WONTFIX, а не deferred:** відкладене повертається в чергу й повторно з'їдає сесію на планування
вже спростованої ідеї.

**Не чіпається:** `animRing()` + `ARC{floor:600,ceil:1600,exp:1}` (arc-fill ready→ready на Home) ·
`fireReward()` + MOTION reward LOCK v2 · §5.2 статика.

**Канон-дія (не зроблено):** зняти hole #1 з `Фармастор_v2_MASTER_LOCK` §9 п.1 та з «Ідея-тріаж»,

## §4 РІШЕННЯ-2 · Нагорода моменту 📋 = handoff-sweep (C)

**Семантика: «ПЕРЕДАНО», не «завершено».** Завершення сталося на 83/83 і вже нагороджене per-brand.

**Чому C, а не E (Border Beam):**
1. **напрям кодує сенс** — смуга виходить за край = вектор «звідси туди»; замкнена петля кодує
   «об'єкт активний», а не «вміст пішов»;
2. **вартість кадру** — C composite-only (transform+opacity на дочірньому шарі); E = per-frame
   repaint по периметру (A70/A72);
3. **трендовий маркер** — border beam у 2025–26 = підпис «AI-інтерфейс», клас ризику лівого accent-rail.

**Три гарди в `fireSweep()`,** кожен закриває свій відмовний режим:
1. `reduceOn()` — при reduced-motion клас не вішається взагалі (подвійний замок із `@media`);
2. `dataset.sweeping` — анти-повтор; без нього подвійний тап накладається на недограний прохід;
3. **запуск лише на УСПІХ** копіювання (`.then` + успішна гілка fallback). Якщо clipboard відмовив,
   а смуга «значення пішли» зіграла — інтерфейс збрехав саме там, де людина йде в Excel.

**Іменування:** `.cta-*` префіксовані. Зворотний аудит проти b26_1: `cta-lbl` 0 · `cta-sweep` 0 ·
`swGo` 0 збігів. `.cta-lbl` **обов'язковий** — голий текстовий вузол не має z-index і пішов би під смугу.
Сторож R7 у матриці валиться, якщо в продукті колись з'являться голі `.lbl{`/`.sweep{`.

## §6 ~~🔴 ВІДКРИТА ДІРА~~ → ✅ ЗАКРИТО 01.08.2026 · діри немає (Node 2.2)

> **Вирок:** device-перевірка підтвердила гілку «вікно `max-age`». Кеш GitHub Pages
> протухає сам за звичайного користування, свіжа версія підтягується без коду.
> **Service worker не заводиться.** Канон: Cookbook **A79** · `Lens_module_maint_v1.md` §1.
> Розбір нижче лишається як опис механізму.

**Симптом (device, GitHub Pages):** самоперевірка ловить нову версію ✓ · анімація ✓ · бейдж «Оновити» ✓ ·
тап → миттєвий ре-рендер на тому ж місці, версія нова ✓ · **але** swipe-up kill → перезапуск → **стара версія**,
і знову пропонує оновити.

**Механізм:** `mtDoUpdate()` → `location.replace(location.pathname+'?v='+ver)`. Query обходить HTTP-кеш →
в межах сеансу все чесно. Але `start_url` у манифесті **без** query; при холодному старті iOS відкриває
чистий `index.html` із кешу. Застосунок — **один файл**, тож кешована оболонка і **є** старий застосунок.
Service worker у білді **відсутній** (грепнуто: `serviceWorker` 0, `caches.` 0).

**⚠ ПЕРШИЙ КРОК — дешевий тест, ДО будь-якого коду.** GitHub Pages віддає `Cache-Control: max-age=600`.
Якщо тест був у межах 10 хв після деплою — кеш ще «свіжий» і не перевалідовувався.
**Повторити kill-тест через 15+ хв після деплою.**
- стара версія лишилась → діра підтверджена, потрібен SW (network-first на HTML);
- оновилось → це було вікно max-age, фіксити нічого.

Різниця між «пів сесії на service worker» і «нічого не робимо».

## §10 КРИТЕРІЇ WSD-АУДИТУ (хребет наступного чату)

Konst: wsd розроблявся для Opus 4.7/4.8; з Opus 5 взаємодія може вимагати інших формулювань,
і документ не є універсальною інструкцією, у якій він упевнений на 100%.

**Відомі режими провалу протоколу-довгограя (з боку моделі):**
1. **правило без тригера** — незрозуміло, *коли* вмикається → застосується не там або промахне;
2. **заборона без причини** — не узагальнюється на суміжний випадок → виконається буквально;
3. **дублі з різним формулюванням** — невизначеність, яке з двох головне;
4. **значення й код у протоколі** — тригера не мають за природою → читаються як шум і **розбавляють сигнал**.

**Робоча форма правила** (так написані найкращі місця wsd — 2.4, 12.10, 13.3):
> **тригер + дія + чому + анти-приклад**

**Два механічні критерії — прогнати по КОЖНОМУ пункту:**
- **К1.** «Чи можу я з цього рядка сказати, **КОЛИ** він спрацьовує?» Ні → тригер або виселення.
- **К2.** «Якщо це правило порушити — **як я про це дізнаюсь?**» Немає детектора → провалиться тихо.

**К2 цінніший і в wsd майже ніде не реалізований.** Прямий доказ: §4 b26_1 — правило про префіксовані
імена класів **існувало**, детектора не було, провалилось тихо, баг доїхав до девайса.

**Доповнення з цієї сесії:** детектор мусить бути **правильним**. R6 у матриці b27 упав на першому
прогоні, бо регекс `.cta-sweep\{` ловив і легітимне `.btn-copy.sweeping .cta-sweep{`. Хибний ✗
привчає ігнорувати червоне — ламається так само тихо, як відсутність детектора.

**wsd НЕ ділити на томи.** Cookbook читається **точково за запитом** → розріз працює.
wsd читається **цілком** як протокол на старті сесії → розріз означає, що частина перестане читатись.
wsd треба **прополоти**: виселити чуже по домах, злити дублі 12.x/13.x, викинути мертве.
