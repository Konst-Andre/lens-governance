- **Підміна UA в jsdom: опції верхнього рівня `userAgent` немає — ігнорується мовчки.**
  *(влито з буфера `Д-В`, G-B2 17.09.2026; веб-пас 12.10 п.5 — формулювання буфера «jsdom 30 більше
  не приймає» виправлено: такої опції не було, злам — у v28)* `[09.2026 · jsdom 30.1.0]`
  `new JSDOM(html,{userAgent:ua})` не кидає помилки, а `navigator.userAgent` лишається
  дефолтним `…jsdom/30.x`. Документований шлях — `resources:{userAgent:ua}`. Клас
  `ResourceLoader` з v28 (реліз-ноти: «Overhauled resource loading customization») з експорту
  прибрано: старий код `new jsdom.ResourceLoader({userAgent})` падає `is not a constructor`.
  Надійний обхід для матриці, що підміняє ще й `platform`:
  `beforeParse(w){ Object.defineProperty(w.navigator,'userAgent',{value:ua,configurable:true}); Object.defineProperty(w.navigator,'platform',{value:pf,configurable:true}); }`.
  **Правило:** матриця, що гілкується по UA, мусить мати **клітину-самоперевірку**
  `navigator.userAgent === ua`, яка **завалиться**, якщо підміна не спрацювала. Інакше стенд
  проходить дефолтну гілку й рапортує зелене там, де перевірки не було. *Прецедент:* матриця
  StockCheck Node 2.2 — 6 «провалів» у гілках iOS/Telegram, усі шість були дефектом стенда
  (`archive/matrices/StockCheck/StockCheck_maint_jsdom_matrix.js`). **Перевіряти при
  мажорному оновленні jsdom.** *Джерела:* README jsdom `main` (§ Loading subresources) ·
  реліз `v28.0.0` (15.03.2026) · замір у пісочниці 17.09.2026: верхній рівень → дефолт,
  `resources:{userAgent}` → ✓, `beforeParse` → ✓, `ResourceLoader` → `undefined`.

### §6-а. Спина harness-шаблону — дев'ять пунктів

*(влито з буфера `Д-Г`, G-B2 17.09.2026; адреси `wsd 2.4b/2.4d` переписано на §8.4-(b)/(d) — розділ перенесено сюди 13.08.2026)*

**Еталон:** `archive/stands/QR_Lens/QR_Lens_brand_harness_v6.html` (v6, не v5).
**Тригер.** Будується **harness** — стенд перцептивного суду одного об'єкта (бренд, гліф,
матеріал), а не bench механіки. Межа bench ↔ harness — драбина §4.

**Спина:**
1. **Об'єкт суду локнутий першим** і названий у хедері. Інакше harness судить усе одразу й
   не судить нічого.
2. **Fidelity-драбина, три погляди:** Loupe (збільшено, щоб *побачити* й тюнити) →
   real-size 1:1 in-context (підтвердити читабельність) → full-context Phone (пропорція).
   1:1 чесний для підтвердження, але марний, щоб побачити дрібний елемент, — тому Loupe живе
   в тому ж harness, не окремим файлом.
3. **Реальні розміри девайсів** (XS + 15 Pro), реальні токени, **обидві теми**.
4. **Повнота важелів:** live-контрол · розділ по темах · умовні суб-важелі · 🔒 на кожен
   важіль (§3-п.13).
5. **Банк пресетів** + 2 фаворити для порівняння.
6. **Складна панель** згортається caret-тоглом і не з'їдає стейдж (§8.4-(d), §3-п.8).
7. **Copy-ALL** (STATE + CSS) — §8.4-(b).
8. **Доказ узагальнення тоглом** — рішення не приклеєне до одного випадку.
9. **input ≠ rebuild** — зміна повзунка не перебудовує стейдж, інакше гине live-відчуття.

**Плюс:** тогл легенди «?» (згорнутий за замовчуванням) · карет-згортання доку в thumb-зоні.
**Уроки v1→v3:** Loupe накладався через `scale()` · прес у harness — JS-клас `.pressing`
(A67), **не** `:active` · важелі **внизу**.

**Детектор (К2).** Harness без п.1 (названий об'єкт суду) або без п.3 (обидві теми) — це
bench, не harness: перцептивну вагу на ньому судити не можна (§4).

### §6-б. Стартові значення стенда копіюються з живого коду, не відтворюються по пам'яті

*(влито з буфера `Д-В2`, G-B2 17.09.2026; джерело — `StockCheck_session_summary_b27.md` §2)*

**Тригер.** Будується bench, harness чи компер для компонента, що **вже існує** в продукті.

**Дія.** Стартові позиції повзунків і базові токени стенда **грепаються з живого білда**
(wsd 12.1), а не пишуться по пам'яті чи з самері.

**Чому.** Оператор судить **дельту** між варіантами, а дельта міряється від нульової точки.
Хибна база робить порівняння беззмістовним, і помилка невидима: стенд справний, числа
правдоподібні. Самері фіксує рішення, але не завжди фінальний стан коду після хвостових
правок.

**Розмежування.** §3-п.14 — смоук не знає чисел (перевіряє механіку). §6-б — стартові
числа стенда беруться з коду. Одне не замінює інше: гейт не зловить хибну базу, бо про
значення він не знає за правилом.

**Анти-приклад.** Відтворення значень «як пам'ятаю з попередньої сесії».

**Детектор (К2).** У шапці стенда — рядок-провенанс `база: <файл> р.<рядки>`. Немає рядка →
значення не грепнуті.
