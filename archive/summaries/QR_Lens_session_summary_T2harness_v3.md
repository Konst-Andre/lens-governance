## 1. Що зробили цієї сесії

Побудували **T2 motion-harness** для щита вибору SR (`#sh-sr`). Три ітерації (device-driven):
- **v1** — повний harness: 3 осі × повзунки × frame-gap трійка × slow-mo × reduce × presets × Copy-ALL × caret-док × легенда. Гейт✓ (node --check + tag-balance + jsdom повна матриця = 0 err).
- **v2** — **редизайн view-шару** після device-review: етал tri-view (Loupe/Real/Phone) виявився непридатним для великого субʼєкта (щит на пів-екрана) — Konst бачив «два крихітні вікна». Замінено на `Повна·L` / `Повна·D` (один девайс на всю ширину стейджа, scale ~0.92, стейдж скролить під сторінку) + `Обидві` (тон-компер side-by-side, half-width). Мертві `sceneBlock`/`realBlock`/`.scene` прибрано (3.7).
- **v3** — **replay-док винесено ПОЗА панель** (`#dock`, fixed top-right). Раніше `↻ Відкрити/Обрати` жили в `.prow`, що ховається при згорнутій панелі → Konst мусив розкривати панель, а вона накриває вміст. Тепер: згорнув панель (▴) → повна сторінка → тапає док, не розкриваючи панель. Copy лишився в панелі.

**Гейт кожної версії:** `node --check` (витягнутий скрипт) + Python tag-balance + jsdom runtime-матриця (усі режими × осі × N × slow × reduce × device × copy/preset/caret) = **0 помилок**.

## 2. Узгоджені РІШЕННЯ (locked-напрям, device арбітрує фінал)

### 2.1 Ідея GPT (2 варіанти анімації відкриття) — розсуджено
Konst показав мокап GPT: **V1 «Hybrid Hero Expand»** та **V2 «Full Morph»**.
- **V1** = фактично наш план (прес→A18-слайд→E1-каскад). Назва оманлива (жоден «hero» не expand-иться). Не нове.
- **V2 Full Morph** (капсула морфить у хедер шіта) = справжня нова ідея, кернел цікавий (origin-continuity, container-transform). **ВІДХИЛЕНО для цього щита**, причини:
  1. Напрямкове протиріччя (капсула вгорі → bottom-sheet внизу; морф floating посеред екрана; решта 3 шіти слайдять знизу — це неconsistency, не per-context).
  2. Викидає device-загартовану close-машинерію (swipe A19, backdrop-dim, A18.1/A20).
  3. Не той механізм — морф = робота VT API (`view-transition-name`), а не ручний FLIP; + вже 2 VT (B28 тема, B47 banner-xfade) → 3-й VT-скоуп = ризик колізії (2.4 флагує).
  4. ROI: щит рідко-open (~2×/тижд, T1✓) — дорога-в-підтримці анімація на рідкій поверхні.
  5. Тонально гучний проти About-Quiet характеру.
- **КЕРНЕЛ V2 врятовано** → вбираємо в **Announce-E3b (header-echo)**: шапка шіта ехом капсули (той самий аватар+імʼя) — «шіт народжений із pill» без морфу/регресу.

### 2.2 Осі T2 (вибір Konst для дослідження)
- **Поява = E1-каскад** (реком.). E2-плита = запасний.
- **Announce = E3a ring** — АЛЕ потребує фіксу timing (див. §3). E3b-echo = кернел-варіант.
- **Вибір = A-тихе АБО D-мінімал** — Konst «майже не бачу різниці» → кандидат спростити (можливо дропнути один).

### 2.3 Precept-и (канон-кандидати 14.18a)
- **Harness-view масштабується під РОЗМІР субʼєкта:** дрібний елемент (гліф) → loupe-магніф; великий (щит / повна сторінка) → один девайс на весь стейдж, НЕ дві мікро-сцени.
- **Еталон-harness (brand_harness_v6) = приклад дисципліни, орієнтир — адаптувати під задачу/потребу, НЕ копіювати 1:1.** (узгоджено з Konst).
- **T2 harness-патерн** як шаблон: 3 осі + settle-важіль + frame-gap трійка на ПОВНІЙ сторінці + replay-док поза панеллю.

## 3. DEVICE-СПОСТЕРЕЖЕННЯ Konst (критичні — вхід у новий чат)

### 3.1 🔴 E3a ring на каскаді майже НЕ ВИДНО (головна проблема)
- Ринг працює (увімкнений), але **виконується ОДНОЧАСНО з каскадом** → поки рядки ще їдуть/фейдяться (translateY+fade stagger), 1-shot пульс кільця вже пройшов → його не видно.
- Помітно лише на **першому** відкритті/обраному; при виборі далі (2-й/4-й/5-й) — не видно.
- **На E2-плиті ринг ВИДНО чітко** — бо плита статичніша (нема конкуруючого руху рядків).
- **Гіпотеза Konst (слушна):** ринг має зʼявлятись **ПІСЛЯ завершення каскаду**, не паралельно. Каскад відпрацював → тоді пульс кільця підсвічує обране.
- **Для нового чату:** нові рішення секвенсування. Кандидати (мої, обговоримо):
  - (a) затримка E3a = total-dur каскаду (`off+(N-1)*step+dur`) перед пульсом;
  - (b) привʼязати старт рингу до finish саме рядка-.sel у стаггері (його власний item);
  - (c) альт-announce, стійкий до руху: persistent E3b-echo + мʼякий settle-glow ПІСЛЯ каскаду;
  - (d) переосмислити чи announce-on-open взагалі потрібен при E1, чи достатньо чистого settle.
- ⚠️ У поточному harness (`playOpen`) announce-offset для E1 = `mul(e1Off)+120` — замалий; звідси й баг. Фіксити в новому harness-раунді.

### 3.2 Параметри каскаду (Konst підібрав на device)
- **dist: НЕ 12 → 24-28** (діапазон до 28, ~26-28). «Здається плавнішим і набагато приємнішим».
  - ⚠️ Поточний повзунок `e1Dist` max=28 — ок, але дефолт 12. У новому harness підняти дефолт ~26.
- **ease: Spring** (`cubic-bezier(.34,1.56,.64,1)`) — обрав для каскаду.
- Детальніші характеристики (off/step/dur, ring-timing) Konst протестує в новому чаті.

### 3.3 frame-gap (з device-скрінів v2, режим «Обидві» = 2 девайси, важкий)
- baseline ~33.0ms (⚠️ високий — Claude in-app webview схоже ~30fps або throttle; на одному «Повна» девайсі має бути легше). max-gap 70-97ms, dropped 2-3, Δ +37…+64ms — але це «Обидві» (2 повні девайси). **На `Повна` (1 девайс) переміряти** — покаже реальну вартість E1 на N=12.
