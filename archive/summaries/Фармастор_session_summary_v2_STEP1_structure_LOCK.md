## 1. РІШЕННЯ #1 — Нурофен: **REORDER within-brand** ✅ (device-safe)

Під-групи Нурофена рендеряться у ФІКСОВАНОМУ канонічному порядку `[Таблетки/капсули, Суспензія, Супозиторії]`, збираючи SKU у свою групу незалежно від сирої позиції → **3 чисті блоки**. Durex вже контигуальний (reorder = no-op).

### Чому це БЕЗПЕЧНО для переносу (grep-доказ, 12.1)
- Значення зберігаються **за kode**: `ST.phs[phId][kode]=val` (не за позицією).
- Стовпчик будується **ітерацією масиву MSL у порядку майстра**, значення тягнуться по kode: `MSL.forEach(s=> …d[s.k]…)` (v1.3 р.587).
- **Порядок відображення ⊥ порядок стовпчика.** Reorder міняє ЛИШЕ рендер акордеона; колонка завжди master-order. Підміна даних неможлива.

Sub-group лічильники («Таб/капс 13/13») рахуються по всій під-групі — коректно після reorder.

## 2. FILL-РЯДОК (вайрфрейм — структура locked, вигляд→крок 2)

iOS **inset-grouped** рядок (НЕ обведена картка), навколо ОДНОГО героя = поле лічби:
```
┌────────────────────────────────────────────┐
│ Нурофен Форте                       ┌─────┐ │
│ №24, таб. 400мг · норма 6           │  8  │ │  ← поле лічби (герой, правий край)
└─────────────────────────────────────┴─────┘ │
  ^назва (жирна, р.1)   ^тихий 2-й рядок        ^великий тап-таргет
```
- Порожнє поле = **ghost-норма** (MSL блідим); ввід → суцільне число.
- «норма N» лишається тихим на 2-му рядку (щоб норма не зникала після вводу — ghost зникає при вводі).
- БЕЗ колонки «→ Замовлення / результат».
- Читабельність на сонці: високий контраст, великі тапи (крок 2).

**Відкрито на крок 2 (візуал):** тримати «норма N» на р.2 ПЛЮС ghost, чи лише ghost + опційний inline-метр (§6 planning). Structurally пропоную персистентну норму на р.2.

## 3. СТАНИ КОМІРКИ (locked, §5 planning)

| Стан | Умова (kode-мапа) | Вигляд поля | Рядок |
|---|---|---|---|
| не торкався | kode **absent** | ghost-норма (блідо) | «активний» |
| ввів >0 | kode present, val>0 | суцільне число | заспокоєний (бліднішає/✓) |
| ввів явний 0 | kode present, val=0 | суцільний «0» = ДАНІ | заспокоєний |

- **БЕЗ автопереходу** після вводу (багатоцифрові кількості).
- Навігація ІНІЦІЮЄ юзер: тулбар «↑ ↓ Готово» (є) + **«↓ наступне незаповнене (N)»** (стрибок на найближчу дірку по всій аптеці, крізь під-групи).
- Опційний чіп **«нема / 0»** біля поля = ствердний нуль як намір.

## 7. СТАТУС ПЕРЕНОСУ + COPY-КОНТРАКТ (locked, §3/§4)

- `transferred` — окремий per-аптека прапорець, НЕ дорівнює `filled`.
- **Copy-контракт (нова функція v2, master-order+by-kode):**
  ```js
  // 83 значення, по одному в рядок, у порядку SKU МАЙСТРА, пропуски = порожні
  MSL.map(s => (d[s.k]!==undefined ? d[s.k] : '')).join('\n')
  ```
  Гарантія: незалежно від reorder/групування відображення (§1). Пропуск = порожній рядок (не затирає чуже нулем).
- Воркфлоу-порада (не код): переносити ОДРАЗУ після кожної аптеки → мінімальне вікно «дані у двох місцях».
- In-app тост після копії: «✓ Скопійовано 83 значення → встав у M168».

**ВИДАЛИТИ у v2 (з §3 planning):** `xlsx-js-style` бібліотека (−425 КБ, весь блок р.10 + експорт-стилі р.562–660), стильний `.xlsx` експорт, колонка «→ Замовлення» в рядку SKU. **ЗАЛИШИТИ:** легкий нативний CSV (страховка) + share-sheet як є.

- Записати як `farmstore_v2`, лишити `farmstore_v1` недоторканим (rollback-safe).
