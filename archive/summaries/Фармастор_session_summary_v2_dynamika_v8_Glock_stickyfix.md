## 1. ЗАЛОЧЕНО ЦІЄЇ СЕСІЇ (device✓ на харнесі; canon-merge ПІСЛЯ порту в продукт)

### 1.1 colhead-ДІМ = **ГЛОБАЛЬНИЙ (G)** — Konst device-pick 19.07
- Реопен G⇄P вирішено: **G перемогло** («мені сподобалось»). P відхилено.
- G = один `.gdome` зверху `#list`, sticky, над усіма брендами. Період спільний → семантично коректно + прибирає повтор шапки на кожній картці.
- Per-brand colhead лишається в DOM (ховається CSS `[data-domescope=global] .colhead{display:none}`) — тумблер живий у харнесі для історії, але **дефолт і лок = global**.
- Геометрія вирівнювання: `.gdome{margin:0 12px;padding:0 14px;border:1px}` → `hcols` прав.край = `viewport−27px` = точно над `.dyn` рядків (12 margin + 1 border + 14 pad = 27; рядки: 12+1+6 rows-pad+8 row-pad = 27). ✓

### 1.3 STICKY-БАГ — **RESOLVED структурно** (2 корені)
- **Корінь 1 (дім не пінився):** `.scroll{flex:1}` без `min-height:0` → флекс-пастка `min-height:auto` → `.scroll` ріс під контент, скролився BODY, sticky не мав відносно чого пінитись.
  **Фікс:** `html,body{height:100%;overflow:hidden;overscroll-behavior:none}` + `.scroll{min-height:0;-webkit-overflow-scrolling:touch}` (канон Cookbook 497/1163, A9). Device✓: G-дім пінится.
- **Корінь 2 (порожнє поле над Нурофеном):** `[data-chsticky=on] .ebrow{top:calc(chH+10)}` offset на ebrow, який жив у `.bbody{overflow:hidden}` → sticky вбитий предком → iOS рендерив offset як мертвий зазор (лише на суб-групних брендах).
  **Фікс:** знято `position:sticky`+offset з `.ebrow` → нормальний дільник. Зазор зник.
- **Урок → Cookbook-кандидат:** харнес мав власний зламаний shell (не port-faithful до продукту) → sticky-баг був частково артефактом харнеса. **Правило:** харнес МУСИТЬ мати канонічний scroll-shell (html/body height:100%+overflow:hidden, inner .scroll min-height:0), інакше sticky-судження недійсне.

### 1.4 P-важіль-баг (діагностовано, фікс НЕ потрібен — G переміг)
- У P+sticky правило форсило `background:var(--cardBg)`, перебивало tint-важіль. У G такого override нема → важелі працювали. Оскільки лок=G — питання закрите (P sticky-override у продукт не йде).

## 2. Δ-КОЛІР — **РЕОПЕН §5.1 ПІДТВЕРДЖЕНО** (наступна сесія: бенч)

### Проблема (device 19.07)
- Поточний лок §5.1 = **дистанція-до-норми** (`moveLevel`: `|t−MSL|<|f−MSL|`→closer/green). Харнес коректний щодо канону.
- **Konst-інтуїція PSR б'є в шов:** 7→4 (MSL5) = зелений (4 ближче до 5), АЛЕ 4<5 = нижче мінімуму = треба дозамовляти. Зелений кричить «ок», а ти впав під норму. Канон розчепив (колір=дистанція / сире число несе «нижче норми») — на девайсі розчеплення не читається.
- Тригер реопену (мій протокол: «реопен §5.1 ЛИШЕ якщо колір читається плутано») — спрацював.
- **Історія:** модель недобору вже пропонувалась 16.07 (`s=max(0,MSL−V)`), потім лок 18.07 повернув дистанцію → питання флікало, НЕ вирішене.

### Рішення напряму
- **Реопен підтверджено обома.** Наступна сесія = **бенч, що показує ОБИДВІ моделі поруч** на реальних числах Konst, обидві теми, device-арбітр:
  - **Модель A — дистанція** (поточна): ближче до MSL=accent, далі=warn/crit.
  - **Модель B — траєкторія недобору** `s=max(0,MSL−V)`: недобір скоротився/закрився=improvement/green · виріс або впав із провіжн у дефіцит=degradation/warn · обидва ≥MSL=stable/muted · застряг нижче=warn · V=0=crit.
- **Claude-рекомендація:** для інструмента «полиця ≥ MSL» модель B (недобір) правильніша — нижче MSL=червоний=дія. Але фінал — device-oко Konst.
- **Ripple:** зміна тягне й ВЕРХНІ ПЛИТКИ (зараз «ближче/далі» = мова дистанції → стануть «дефіцит/у нормі» абощо) + фільтр «Проблемні» (t<норма). Бенч має показати і плитки.
